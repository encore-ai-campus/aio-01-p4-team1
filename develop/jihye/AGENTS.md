# 지혜님 · 파일 소유권 규칙

저장소 루트 AGENTS.md를 함께 따른다. 주 역할: 백엔드·DB·실행 환경.

- 시작 시 README와 Doc/TODO·SPEC·IMP-PLAN·HANDOFF를 읽는다. 공통 docs의 계약은 읽기 전용 기준이다.
- 편집 허용 범위는 develop/jihye/뿐이다. 다른 이름 폴더·루트 문서·설정·공통 제출 파일은 직접 수정·생성·삭제·이동하지 않는다.
- 상대 파일이 틀렸거나 계약 변경이 필요하면 내 Doc/HANDOFF.md에 재현·제안·영향·검토 상대를 적는다. 상대가 자기 폴더를, 오현님이 공통 파일을 수정한다.
- 현재 폴더 안에서만 프로젝트·패키지·Mock·테스트를 생성한다. 상대의 프로젝트를 복사하거나 루트에 package.json/가상환경/빌드 파일을 만들지 않는다.
- 팀장이 배포한 기본안 그대로 구현할 때는 별도 재승인이 필요 없다. 기본안을 바꾸려 할 때만 변경 요청하며 미승인 변경안을 확정처럼 구현하지 않는다.
- 지정한 한 단계만 구현하고 실제 확인과 미실행을 구분한다. push·test는 팀 규칙대로 사람이 수행한다.
- PR 전 수정·스테이징 경로가 허용 범위 안인지 확인한다. 팀 VM 배포·main 병합은 오현님이 한다.

## 개인 문서로 작업하는 순서

- 루트 AGENTS의 시작 전 필수 문서 확인은 유지한다. 이후 작업 범위는 README → IMP-PLAN의 지정 단계로 정하고, 입력·출력·정상/오류 기준은 SPEC에서 찾는다. DB/실행 세부는 migrations/README·deploy/README를 따른다.
- SPEC은 백엔드에 필요한 공통 확정 사항을 모은 적용 기준이다. 출처·대조 기준 커밋을 남긴다. 공통 원문과 다르면 누락/오기를 정리하고, 원문끼리 불명확하거나 계약을 바꿔야 하면 HANDOFF로 요청한다. 문서 정리가 다른 단계 구현의 허가는 아니다.
- ‘기준 확정 / 제안’과 ‘미구현 / Mock 검증 / 실제 연결 검증’을 별도로 기록한다. 공통에 반영된 기본 기능을 옛 H01~H06 제안 때문에 대기시키지 않는다. 과거 기록은 작성 당시 이력으로 보존한다.
- 각 단계는 전제 조건·수정 파일·수행/제외 범위·검증·완료 기준·인계를 확인한 뒤 구현한다. 사용자 지정 단계를 완료하면 결과와 다음 단계를 보고한다.
- 팀원이 확인했다고 전달받은 결과는 전달 출처·대상 커밋과 함께 적는다. 직접 코드 검토·재실행·실연결 결과로 바꾸어 쓰지 않는다.
