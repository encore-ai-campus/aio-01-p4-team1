# 업무 API·DB·공통 실행 설정 · IMP-PLAN

작업 기준: [내 작업·협의 안내](WORK-GUIDE.md) · [내 협의 기록](HANDOFF.md). 공통 파일과 상대 폴더는 직접 고치지 않고 소유자에게 요청한다.

주 담당: **지혜님**. 지원 담당은 추가 배정.

> 상태: 단계 구성 초안. 모든 단계 미실행. 담당자가 SPEC의 요구 ID·실제 수정 파일·확인 명령을 채운 뒤 한 단계씩 구현한다.

## 파일 경계 · 저장소 루트 기준

`develop/jihye/`, `develop/jihye/migrations/`, `develop/jihye/deploy/`의 실행 설정. 팀 VM의 실제 배포·환경값 등록은 리드가 관리한다.

DB 초기화 단계에 pgvector 확장과 문서 청크·벡터 테이블을 포함한다. 유빈님과 벡터 차원·메타데이터·검색 권한을 합의하고 업무 테이블과 분리한다.

## 1단계 · 계약·저장 구조

- [ ] 할 일: 화면 담당·안정성 담당과 각 API 예시를 작성하고 DB 관계·제약·인증을 정한다.
- [ ] 연결된 SPEC ID: 담당자 작성
- [ ] 생성·수정 파일: 담당자 작성
- [ ] 확인 명령·시나리오: 담당자 작성
- [ ] 통과 기준: 정상·권한·오류 예시와 테이블 관계 검토
- [ ] 실제 확인 결과·남은 문제·커밋: 실행 뒤 기록

## 2단계 · 실행 뼈대·DB·인증

- [ ] 연결된 SPEC ID: 담당자 작성
- [ ] 생성·수정 파일: 담당자 작성
- [ ] 확인 명령·시나리오: 담당자 작성
- [ ] 통과 기준: 새 DB 초기화와 로그인·401·403 확인
- [ ] 실제 확인 결과·남은 문제·커밋: 실행 뒤 기록

## 3단계 · 업무 저장·n8n 연결

- [ ] 연결된 SPEC ID: 담당자 작성
- [ ] 생성·수정 파일: 담당자 작성
- [ ] 확인 명령·시나리오: 담당자 작성
- [ ] 통과 기준: 동일 key 중복 방지와 본인 조회·n8n 정상/실패 확인
- [ ] 실제 확인 결과·남은 문제·커밋: 실행 뒤 기록

## 4단계 · 팀 통합

## 단계별 에이전트 요청 예시

```text
이 역할의 SPEC.md와 IMP-PLAN.md, 공통 API-CONTRACT.md를 읽어.
내가 지정한 한 단계만 구현해. 담당 경로를 지키고 공통 계약 변경이 필요하면 영향을 알려줘.
수정 파일·검사 결과·내가 실행할 확인 명령을 보고해.
구현과 실제 확인을 구분하고, 확인 전 통과 체크를 하지 마.
```

단계 완료 후 담당자가 직접 확인하고 커밋한다. n8n push·test는 수업 규칙대로 사람이 수행한다. 다음 단계 진행 여부는 담당자가 판단하며, 기능이 연결되면 관련 회귀 시험을 한다.
