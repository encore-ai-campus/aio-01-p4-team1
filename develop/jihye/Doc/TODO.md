## 현재 우선순위 · 2026-11-06

P0-1~7과 P1-1~3의 개인 로컬 구현·검증 결과는 IMP-PLAN에 기록돼 있다. P1-4 로컬 전체 회귀는 223 passed·2 skipped·warning 1건이며, DB 재시작·C02 Mock web-flow·별도 DB backup/restore를 각각 확인했다. 원본 RAG 문서·청크가 0건이라 저장 벡터 복원은 미검증이다. 팀 VM의 제한된 인증·문의·티켓 API 흐름은 루트 [VM 시험 기록](../../../docs/VM-TEAM-TESTING.md)에 별도 보고돼 있으나, 정상 RAG 근거 답변이나 전체 공통 시나리오 통과를 뜻하지 않는다.

현재 우선순위는 (1) 팀이 정한 시험 창에서 미확인 VM 연결·공통 평가를 담당자와 대조, (2) 실제 RAG 문서·청크가 로컬에 준비될 경우 저장 벡터를 포함한 backup/restore 추가 확인이다. 별도 로컬 DB backup/restore 구조 비교는 완료했지만 RAG 행 0건으로 실제 문서/벡터 보존은 확인하지 못했다. 반복 가능한 로컬 업무 mock seed는 개인 전용 DB에 적용했다. CI 백엔드/DB 자동 검사와 CD 자동 배포는 별도 미구현이며, 로컬 seed를 자동 배포 경로에 연결하지 않는다.

## 목적과 사용자

직원 6명은 관리자에게 계정을 받아 로그인하고 자기 문의·답변·티켓만 본다. IT팀 관리자 2명은 계정을 발급하고 티켓·알림을 처리한다. 브라우저가 보낸 이름·부서·역할을 신원으로 믿지 않는다. FastAPI가 세션을 확인하고 PostgreSQL에 새 기록을 저장하며 n8n이 판단한 공통 응답을 보존한다.

DB가 비어 있는 새 환경에서도 확장·스키마·직원·첫 관리자를 같은 순서로 준비할 수 있어야 한다. 서버·DB 재시작 뒤 업무 기록과 문서 벡터가 유지되어야 한다. 서비스 간 계약은 공통 기준을 적용하고, 상대가 준비되지 않은 동안에는 Mock으로 자기 기능을 개발한다.

## 후순위

- 필수 동작·권한·시연이 끝난 뒤 목록 페이지 나누기, 운영 규모 백업 자동화, 성능 최적화를 검토한다.
- 로컬 업무 mock은 `deploy/seed_local_mock.sql`을 명시 실행한다. Alembic DDL 및 직원 seed와 분리되어 있고 개인 전용 DB명·migration owner·head 검사로 제한한다. 계정/비밀번호와 RAG 문서·벡터는 포함하지 않는다.
- CI의 백엔드·임시 PostgreSQL 검증은 로컬 시험 절차가 안정된 뒤 추가한다. CD 자동 배포는 팀장 소유의 VM 배포 권한·승인·복구 정책이 정해진 뒤 별도로 검토한다.
- 근사 벡터 검색은 초기 필수가 아니다. 3072차원 HNSW를 바로 추가하지 않고 타입/차원·검색 품질 변경을 C06으로 요청한다.
- 텔레그램·SSO·외부 업무 서비스는 현재 필수 범위에 추가하지 않는다. 비밀번호 P0/P1 필수는12자·3종·본인 이름/로그인ID 포함 금지이며, 이력·잠금·외부OTP는 공통 API §8의 P2 범위다.

## 작업 중 판단

DB/임베딩 모델/포트/기존 API는 선정할 일이 아니다. [공통 API](../../../docs/API-CONTRACT.md)와 [DB 기준](../../../docs/DATA-AND-DB.md)을 그대로 적용한다. 누락 정책은 [HANDOFF](HANDOFF.md)의 구체 제안으로 관리한다. 답변이 없다고 승인으로 보지 않으며, 미확정 정책에 의존하지 않는 골격·기본 스키마·모델·Mock 작업부터 계속한다.

기존 문의 처리·색인·검색·이관 워크플로우를 이 폴더에 복제하지 않는다. 화면은 수언님, AI 흐름은 다혁님, RAG는 유빈님, 이관/공통 시험은 원민님, VM·공통 문서는 오현님 소유다. 본인 문서는 백엔드의 실제 확인 증거만 제공한다.
