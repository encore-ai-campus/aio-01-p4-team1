시간은 수업 목표에 맞춘 요청안이다. 수언님·지혜님에게 80일차 웹/업무 기능 전체 완성을 요청하는 뜻은 아니다. 지연되면 현재 결과·막힘·다음 담당을 받고 발표에 반영한다.

## 배포 전에 먼저 확인할 연결

1. 오현님·원민님: 공식 80일차 flow.py와 common.json의 실제 배포 위치·버전·원본 해시를 확인한다. 다혁님 폴더의 tools/flow.py는 독자 로컬 도구이므로 공식 검사 도구로 바꿔 부르지 않는다.
2. 오현님·다혁님: oke-support.json은 P0-1 보존본, oke-support-02.json은 확인 시점의 P0-2 개발본이다. 내부 웹훅이 같으므로 두 파일을 한꺼번에 게시하지 않는다. 이번 VM 목표에 맞는 한 버전과 Mock/실제 전환을 소유자가 지정한다.
3. 지혜님·유빈님: DB 확장·테이블·권한과 실제 색인 실행 경로를 확인한다. 현재 유빈님 Mock 래퍼가 요구하는 실행 환경도 확인해야 하며 JSON 존재만으로 VM 색인 완료가 아니다.
4. 다혁님·원민님: support→handoff 호출과 응답 매핑의 실제 구현 여부를 확인한다. handoff의 Mock 보고서를 본체 통합 결과로 사용하지 않는다.
5. 오현님: 검토·병합한 main 커밋으로 배포하고 원민님과 VM에서 입력/차단 결과를 확인한다. 미완성 실제 연결을 성공으로 보완해 설명하지 않는다.

## 팀원에게 받을 공통 형식

담당자가 자기 폴더의 Doc/SUBMISSION-NOTES.md 또는 기존 HANDOFF에 아래 항목을 적고 경로·커밋을 공유하도록 한다. 다른 담당자의 파일을 대신 작성하지 않는다.

```text
담당 / 단계 / 기준 커밋:
변경 파일·볼 자료 경로:
계획·Mock·실제 중 어느 상태인지:
확인 환경·명령·입력:
기대 결과 / 실제 결과 / 보고서·가린 캡처:
미실행·실패·막힌 이유:
필요한 상대 / 받을 것 / 다음 확인 시점:
```

수신 후 오현님은 주제·설계 변경을 main의 공통 문서에 반영하고, 실제 당일 진행·실패·다음 행동은 [DAY80](../../../docs/daily/DAY80.md)에 기록한다. 공통 문서 복사본을 이 폴더에 만들지 않는다.
