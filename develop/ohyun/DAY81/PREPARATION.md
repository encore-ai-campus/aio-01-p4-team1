# 81일차 · 팀장 준비·운영 체크리스트

오늘 공개할 자료는 [발표 README](README.md), 역할별 인계는 [TEAM-INPUTS](TEAM-INPUTS.md), 점검/발표 순서는 [PRESENTATION](PRESENTATION.md)에서 확인한다. 이 문서는 작업용이며 실제 기록은 [공식 DAY81](../../../docs/daily/DAY81.md)에 남긴다.

## 시작 전

- [ ] DAY80의 강사 피드백·미완료·담당자를 확인한다.
- [ ] 공식 키트·공통 원본·Webhook·VM 기준 커밋·practice/app을 확인한다.
- [ ] 원민님과 VM 공통 시험의 출발점을 확인하고 실제 보고서를 연결한다.
- [ ] 오늘 필수 연결과 먼저 고칠 실패를 정하고 각 소유자에게 필요한 결과를 공유한다.

## 4교시 중간점검 전

- [ ] 다혁님에게 실제 연결선의 입력/출력·변환·분기 자료를 받는다.
- [ ] 유빈님에게 RAG 3~5절의 모델/차원·권한·인덱스/메타데이터·재색인/복구 자료를 받는다.
- [ ] 지혜님·원민님에게 외부 연동 대상·인증·성공/실패·모드별 저장 결과를 받는다.
- [ ] 수언님·지혜님에게 웹 입구/저장 API가 실제 연결된 범위와 Mock인 범위를 받는다.
- [ ] 검토·병합한 기본 브랜치로 VM 1회 배포 후 공통 회귀를 확인한다.
- [ ] 팀별 10분 점검에서 페이로드 표·RAG 3~5절·연동 표와 현재 실패를 보여 준다.

## 7~8교시 발표·동결 전

- [ ] 권한·본인 조회·가림·주입·장애·중복·보완 한도를 실제로 확인한다.
- [ ] Error Workflow 게시·부모 설정·안전한 종료를 확인한다. 게시 주체는 사람이다.
- [ ] 설계서 2종이 실제 JSON/노드·API·DB·측정과 일치하는지 대조한다.
- [ ] 원민님 결과서 초안에 실제 통과/실패·보고서·대표 로그가 연결됐는지 확인한다.
- [ ] 기본 브랜치로 VM 2회차 배포 후 전체 공통 회귀를 확인한다.
- [ ] 10분 발표에서 정상·예외·RAG·실패·통과 수를 근거로 설명한다.
- [ ] 기준 커밋·완료/미완료·필수 수정·소유자·82일차 첫 작업을 DAY81에 기록하고 기능 동결을 알린다.

## 아직 결과를 기다려야 하는 것

| 기다리는 것 | 제공/확인 상대 | 그동안 진행할 일 |
| --- | --- | --- |
| 실제 화면·인증·저장·DB 기반 | 수언님·지혜님 | 공통 계약과 시연할 화면/기능 대조 |
| 본체·Agent·연결선·분기 결과 | 다혁님 | 설계서·입출력 형식·게시 버전 검토 |
| 실제 검색·청킹 비교·권한·복구 수치 | 유빈님·지혜님 | 기존 설계와 측정 조건·비교 표 준비 |
| 실제 n8n/VM 공통·팀·장애 보고서 | 원민님·기능 담당 | 입력·기대·발표 순서·실패 전달 형식 정리 |
| 강사 점검 피드백 | 강사 | 질문·현재 막힘·가능한 범위 축소안 준비 |

Mock/로컬 검사만 확인한 부분은 그 단계로 기록한다. 실패는 소유자가 수정하고 동일 조건으로 재시험하며, 실제 결과가 없는 항목을 동결 전에 완료로 바꾸지 않는다.

공통 문서 수정은 main에서만 하고 submission으로 역병합하지 않는다. 당일 변경 공지가 있으면 목표와 피드백을 DAY81에 반영한다.
