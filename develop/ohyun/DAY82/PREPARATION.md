- [ ] doctor ready·고장 해제·LLM 정상·실제 색인·세션/계정 접근·시연 요청을 확인한다.

- [ ] 실패 시 설명할 실제 로그·보고서와 수정/미완료 범위를 준비한다.
- [ ] 키·비밀번호·VM 접속 정보·연락처가 화면·문서·로그에 노출되지 않게 확인한다.

## 5교시 · 14:50까지 최종 제출

- [ ] 필수 수정은 소유자가 원본에서 진행하고 main에 검토·병합한다.
- [ ] docs/는 main에서 최종 정리하고 submission에는 main → submission merge로만 반영한다.
- [ ] 검토된 실제 파일을 제출 경로로 취합하고 소스 커밋을 기록한다. 빈 JSON·예시·Mock을 구현물로 대신 넣지 않는다.
- [ ] frontend/backend/deploy 재배치 뒤 import·Compose context·마이그레이션·시나리오 경로·실행 명령을 검증한다.
- [ ] 최종 제출 저장소의 기본 브랜치(Default branch)와 강사 접근 권한·비공개 요건·제출처를 확인한다.
- [ ] 검증한 제출 결과를 제출처 기본 브랜치에 반영한다. submission → 개발 main 역병합은 하지 않는다.
- [ ] 제출처 기본 브랜치의 검증한 커밋과 VM에 시연할 코드가 일치하는지 확인하고 그 기준으로 최종 회귀를 확인한다.
- [ ] 실제 tscan scan . 결과·필수 파일·가린 캡처·보고서를 확인한다. 최종 공지에서 PDF를 요구하면 같은 docs 원본으로 내보내 형식을 확인한다.
- [ ] DAY82를 제출 전에 실제 내용으로 작성하고, 마감 전 최종 커밋·제출 확인을 기록한다.

main에서 작성한 최종 기록도 submission merge와 제출처 기본 브랜치 반영을 거쳐 같은 문서로 맞춘다. 제출한 뒤 새 실행 결과를 덧붙이느라 마감 커밋을 변경하지 않는다. 준비·검증·반영을 14:50 전에 마칠 시간을 확보한다.
