# 82일차 · 20분 발표·시연·질의 준비

발표 본문은 [README](README.md), 공식 결과는 [EXECUTION-RESULT](../../../docs/EXECUTION-RESULT.md)다. 이 문서는 리허설·진행용이고 결과를 별도로 확정하는 문서가 아니다.

## 발표 전 열어 둘 것

- GitHub 최종 제출 커밋의 발표 자료·헌장·필수 산출물3종·실제 캡처.
- 팀 VM n8n의 선택한 게시 버전·Executions·정상/예외/이관 로그.
- 구현된 경우 직원/관리자 실제 웹 화면·안전하게 준비한 로그인 세션.
- 실제 시연 요청·원민님 runs와 가린 저장 관측·재현 절차.

실제 키·암호·VM 접속 정보·연락처는 공개하지 않는다. Credential 내용 대신 설정 역할·성공/실패 결과를 설명한다.

## 수업자료 권장 20분 구성

| 시간 | 말할 내용 | 근거 |
| --- | --- | --- |
| 0~3분 | 어느 회사의 누구를 위한 어떤 지원인지, 해결 문제·범위·팀 역할 | TOPIC·TEAM-CHARTER·실제 구현 범위 |
| 3~8분 | 수신→검사→분류→검색→작성/검증→이관, 역할·분기/병렬/루프·연결선1개 | WORKFLOW-DESIGN·실제 JSON/입출력 |
| 8~12분 | 왜 이 청킹을 썼는지 실제 비교, 모델·차원·권한 선필터·재색인 | RAG-ARCHITECTURE·실제 수치/근거 |
| 12~17분 | 아래 7단계 중 실행 장면을 실제 VM에서 진행하고 결과 설명까지 연결 | 시연 요청·VM·실행 결과서 |
| 17~20분 | 최종 통과/실패·시간·대표 실패/수정/재시험·남은 위험 | 실제 runs·EXECUTION-RESULT |

시연 7단계의 마지막 결과 설명은 17~20분 구간으로 이어서 진행할 수 있다. 청킹·처리시간 수치는 실제 보고서에서만 읽고, 임의 예시 숫자를 발표에 남기지 않는다.

## VM 시연 순서 · 원본 요구 7단계

| 단계 | 준비할 입력·화면 | 확인할 것 |
| --- | --- | --- |
| 1 정상 문의 | 원민님 정상 요청 또는 실제 웹 질문 | 직원·질문 수신 |
| 2 처리 흐름 | n8n 해당 실행 | 분류·검색·작성·검증의 실제 노드 |
| 3 근거·답변 | 응답·허용된 원문 절·화면 | 출처와 답의 대응 |
| 4 보완 질문 | 정보 부족 요청·다음 차례 입력 | 구체적 질문·attempt/context·한도 |
| 5 예외 | 무근거 또는 통제된 외부 장애 요청 | 추정 금지·사유·재시도 상한·정해진 응답 |
| 6 업무 이관·로그 | 실제 티켓·알림/DLQ·가린 실행 기록 | 실제 저장·같은 키 중복 방지·실패 상태 |
| 7 결과·실패 설명 | 최종 보고서·대표 실패 전/후 | 원인·소유자 수정·같은 조건 재시험 |

시연 전 doctor ready·fault all ok·llm up·색인 준비를 실제 확인한다. 장애 주입은 같은 대상에 한 가지씩 하고 끝나면 해제한다. 환경 키나 안전한 접속값을 발표 파일에 직접 쓰지 않는다.

## 리허설 후 남길 것

실제 소요시간·막힌 단계·시연 요청·수정 소유자·재확인 결과를 DAY82에 남긴다. 실패하면 현상과 남은 위험을 설명하며, 설계 화면·Mock을 실제 성공으로 대신 보여 주지 않는다. 마감 후 제출 커밋을 고치지 않고 제출한 버전으로 발표한다.
