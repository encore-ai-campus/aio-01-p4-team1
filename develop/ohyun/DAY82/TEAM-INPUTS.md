# 82일차 · 최종 받을 자료

최종 수치와 캡처는 당일 실제 결과를 받는다. 미래의 PASS·배포·제출을 미리 기록하지 않는다. 공통 문서 원본은 main의 docs/이며 담당자는 자기 개발 폴더의 자료·커밋으로 인계한다.

시점은 우리 팀 요청 목표다. 실제로 준비되지 않은 부분은 담당·이유·영향·다음 조치를 받아 필수 수정 또는 미완료로 분류한다. 오전에 새 기능을 추가하지 않는다.

## 결과와 함께 받을 식별 정보

```text
담당 / 실제 최종 소스 커밋 / 인계 파일:
실행 환경·의존성 / 실제 명령 / practice 또는 app:
DB 마이그레이션·원본/색인/모델·설정 버전:
정상·예외·권한·중복·반복 검증의 기대/실제:
원 보고서·실행 ID·가린 캡처:
최초 실패 / 수정 소유자·커밋 / 동일 조건 재시험:
미구현·미실행·Mock 전용·남은 위험:
발표에서 보여 줄 실제 장면과 재현 절차:
```

## 취합 때 구분할 것

- 최종 수치: 원민님 실제 runs → 공통 EXECUTION-RESULT. Mock/단위 테스트 건수와 합치지 않는다.
- RAG: 유빈님 측정·지혜님 DB 근거 → 공통 RAG-ARCHITECTURE. 추정·계획과 실측을 구분한다.
- 실제 노드·페이로드: 다혁님/관련 담당 → 공통 WORKFLOW-DESIGN. 설계 그림의 노드 수를 실구현으로 쓰지 않는다.
- 화면: 수언님 실제 캡처 → docs/images/. 기존 planned/는 설계 소개용이며 실행 증거로 집계하지 않는다.
- 시연: 원민님 요청·지혜님 실행법·각 기능 담당 재현 → 오현님 VM 리허설.
- 제출 사본: 검토된 main 원본 → submission 취합·재검증 → 제출처 Default branch. docs/는 merge로만 반영한다.
