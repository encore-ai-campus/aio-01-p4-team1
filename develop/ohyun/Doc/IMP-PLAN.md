아래는 앞으로 진행할 작업이다. 실제 GitHub 설정·기능 구현·VM 배포·시험은 아직 미실행이다.

## P0-1 · 문서와 기준 배포 (LEAD-01~03)

- 입력: 공통 계약·DB 기준·6명 개인 문서.
- 수정 파일: develop/ohyun 문서와 필요한 루트 공통 문서. 다른 개인 보완은 해당 담당자에게 요청한다.
- 확인: 개인 SPEC에 기존 기준을 다시 선정하라는 지시가 없는지, 첫 단계 파일/입출력/검증이 연결되는지 읽는다.
- 완료 기준: 각 역할이 같은 계약을 적용해 자신의 첫 단계부터 시작 가능.
- [ ] 실제 결과·남은 변경 요청·기준 커밋 기록

## P0-2 · GitHub 작업판·PR 기준 (LEAD-04·08)

- 마일스톤 제안: P0 공통 기반, P1 필수 구현·안정성, P2 고도화, 제출·발표.
- GitHub에 실제 생성한 뒤 URL·기한·완료기준을 이 절에 기록한다. 현재 생성 완료로 간주하지 않는다.
- 이슈는 담당자/범위/요구ID/예상결과 한 묶음, 브랜치는 feat/<개인폴더>-<작업명>.
- 개인 PR에는 자기 폴더만 포함. 공통 계약 변경은 오현님이 별도 반영.
- main 보호·필수 리뷰/검사 설정은 저장소에서 실제 지원·설정 여부를 확인하고 기록.
- [ ] 실제 이슈/마일스톤·보호 설정·첫 통합 시각 기록

## P1-1 · 독립 기능 검토 (LEAD-04)

| 먼저 검토할 묶음 | 확인할 것 | 뒤에 연결할 담당 |
| --- | --- | --- |
| 지혜님 API·DB·pgvector·seed·실행 설정 | 스키마·신원·멱등·health·재시작 유지 | 수언님·유빈님·원민님 |
| 유빈님 index/search | 권한·메타데이터·근거 응답·재색인 | 다혁님 |
| 원민님 handoff/errors | 정상·중복·티켓/알림 실패·DLQ·오류 트리거 | 다혁님·지혜님 |
| 다혁님 support 골격·Agent·분기 | 공통 응답·주입/입력·분류/검증·보완 | search/handoff 제공자·지혜님 |
| 수언님 Mock 화면 | 상태별 렌더링·필수 화면·API 대응 | 지혜님 실제 API |

저장소 루트에서 검토할 명령:
```bash
git status --short
git diff --name-only
git diff --check
```
기능 시험 명령은 각 역할 README의 실제 명령을 따른다. 문서 검사 통과를 기능 통과로 쓰지 않는다.
- [ ] PR마다 SPEC의 PR 검토 항목·실제 근거·다음 연결 상태 기록

## P1-2 · 실제 연결과 VM (LEAD-05·06)

1. 제공자 실제 응답을 확인한 뒤 소비자의 Mock을 실제 주소로 교체한다.
2. API→support→search/handoff와 직원 화면→API→DB 흐름을 확인한다.
3. 팀 VM에서 기본 브랜치를 갱신하고 지혜님 deploy README대로 마이그레이션·seed·Compose를 적용한다.
4. 원민님과 practice(data-api fault/ops)·app(FastAPI/DB) 설정을 구분하고 회귀를 수행한다.
5. 배포 커밋·설정 모드·실제 명령·통과/실패·보고서를 남긴다. 실패는 소유자 수정 후 재시험한다.

DB 데이터를 지우는 down -v를 기본 배포 절차에 넣지 않는다. 키·VM 접속 정보는 기록하지 않는다.
- [ ] 실제 배포·회귀·실패/재시험 기록
