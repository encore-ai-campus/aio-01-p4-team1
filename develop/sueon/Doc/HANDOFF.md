# 수언님 · 변경 제안·전달 기록

기준: [README](../README.md) · [SPEC](SPEC.md) · [공통 API](../../../docs/API-CONTRACT.md) · [데이터·DB](../../../docs/DATA-AND-DB.md) · [변경 절차](../../../docs/COORDINATION.md).

이 파일은 수언님만 수정한다. 상대는 자기 HANDOFF에 검토 결과와 반대편 링크를 남기고 오현님이 공통 기준을 반영한다. 아래는 **2026-11-03 문서 정비 중 작성한 제안이며 검토·합의·공통 반영·실제 연결 확인은 모두 미완료**다. 외부 메시지를 전송하지 않았다. 응답이 없다고 동의 처리하지 않는다.

## 기존 기준으로 바로 진행할 일

C01의 로그인·질문·내 문의·관리자 API 경로, user 요약·쿠키·items·웹 오류·공통 질문 응답, C07의 서비스·포트·프록시는 재승인을 요구하지 않는다. 특히 계정 비활성화·초기화 API는 공통 계약에 이미 있다. 아래 제안 부분만 Mock/어댑터로 격리하고 IMP-PLAN P0-1부터 계속 진행한다.

## H01 · 관리자 계정/직원 선택 목록

- 기존: POST /api/admin/users, PATCH /{id}, POST /{id}/reset-password는 있으나 기존 계정과 미발급 직원을 조회할 웹 API가 없다. 브라우저에서 data-api 직접 호출은 금지다.
- 재현 조건(설계상): 관리자 페이지를 새로 열면 어떤 직원이 발급됐고 어떤 id를 변경해야 하는지 얻을 수 없다. 실제 서버 재현은 미실행이다.
- 제안: IT 관리자 전용 GET `/api/admin/users`→`{items:[{id,employee_id,login_id,name,dept,role,is_active,must_change_password}]}`와 GET `/api/admin/employees`→`{items:[{id,name,dept,user_id}]}` 추가. 직원은 제공된 6명만 반환, user_id는 미발급 시 null. 비밀번호/해시/세션은 반환하지 않는다. 후자는 계정 발급 대상과 IT팀 담당자 선택에 사용한다. 비로그인 401·직원 403, 정상/빈 목록 200·items 형식 유지.
- 영향: 지혜님은 두 조회 경로·권한·DB employee/user 연결을 추가하고, 수언님은 두 선택 목록과 계정 상태를 연결한다. 기존 생성/변경 API 의미와 원본 6명은 유지한다. 오현님은 API-CONTRACT C01 표에 반영한다.
- 기다리는 부분/계속할 부분: 실제 목록 연동만 대기. Mock으로 발급·비활성화·초기화 UI와 기존 POST 반환 계정의 현재 화면 조작을 개발한다. 미승인 GET을 실제 서비스에 호출하지 않는다.
- 검토 상대: 지혜님(C01), 오현님(공통 반영). 상대 근거: 없음. 공통 반영 커밋: 없음. 실제 연결: 미실행.

## H02 · 요청·응답 상세 필드와 HTTP 오류

기존 공통 계약의 경로·items·필수 응답은 그대로 두고 아래 빈 부분만 구체화하는 제안이다. 표의 JSON 키·타입·오류 코드는 **확정 계약이 아니며** Mock 내부 모델과 향후 어댑터에서 구분한다.

| 대상 | 기존 | 제안 |
| --- | --- | --- |
| 로그인/변경 | user 요약 정의, 최상위 포장·현재/새 키·변경 응답 미명시 | 로그인 `{user:{id,name,dept,role,must_change_password}}`. 변경 `{current_password,new_password}`→`{ok:true,must_change_password:false}` |
| 계정 생성/변경 | 제공 직원 식별값·로그인 ID·임시 비밀번호, 계정 요약 | 생성 `{employee_id,login_id,temporary_password}`. 계정 요약은 H01 users 항목. employee_id는 업무 employees.id, 비밀번호는 응답 금지. 초기화 응답 `{ok:true,must_change_password:true}` |
| 내 문의 | 본인 문의·답변·티켓 상태 목록, items | 항목 `{request_id,question,attempt,context,result,created_at,ticket_status}`. result는 공통 응답 전체, ticket_status는 웹 status 또는 null. 기존 티켓 표시가 필요하면 원본 상태임을 구별하는 별도 필드 추가 검토 |
| 티켓 | id·담당자·상태·답변의 정확한 타입 미명시 | 항목 `{id,ticket_id,title,category,priority,status,assignee,reply,requester_name,created_at,updated_at}`. 경로 id는 업무 티켓 정수 PK, ticket_id는 문자열. assignee는 IT팀 employee 정수 id 또는 null(해제), reply는 문자열 또는 null. PATCH에 없는 선택 필드는 기존 값 유지, 명시 null은 지움 |
| 알림 | 알림 items만 정의 | 항목 `{id,ticket_id,workflow,node,message,severity,created_at}`. ticket_id는 표시용 문자열 또는 null, message는 서버 마스킹. 티켓 생성 실패도 반환 |
| HTTP 오류 | 400/401/403/404, 웹 error·교사 codes | 400 invalid_input/password_policy/duplicate_user, 401 unauthorized, 403 forbidden, 404 not_found로 명시. 중복 발급은 신규 409를 도입하지 않고 기존 400 사용 제안. 교사 400 codes는 원형 유지 |

- 입력/출력 예: PATCH `/api/admin/tickets/21`에 `{status:"in_progress",assignee:null,reply:"확인 중입니다."}`→선택 필드 규칙대로 변경된 객체. 화면에는 ticket_id를 따로 표시한다. 숫자 21은 Mock 식별자 예시이며 실제 데이터가 아니다.
- 영향: 지혜님 Pydantic/OpenAPI·직렬화·NULL 처리·오류 매핑, 수언님 types/각 API 어댑터, 원민님 경계 시험에 영향. 오현님은 API-CONTRACT C01의 상세 예시로 반영한다. 새 업무 DB 테이블은 제안하지 않는다.
- 계속할 일: 질문 공통 응답과 빈 items는 그대로 사용. 비어 있지 않은 업무 목록·변경 필드만 제안 Mock 타입에 둔다. 실제 제공 응답이 기존 계약을 만족하면 어댑터를 맞추고, 제안과 다르다는 이유로 서버 버그라고 단정하지 않는다.
- 검토 상대: 지혜님, 원민님, 오현님. 상대 확인/반영 커밋: 없음. 실제 연결: 미실행.

## H03 · 최초 변경·비밀번호 정책·계정 보호

- 기존: 임시 비밀번호 첫 로그인 변경, HttpOnly 세션, IT팀 admin은 확정. /me는 must_change_password를 명시하지 않는다. 세션 만료·정책 위반 코드·기존 세션 폐기·마지막 관리자 보호의 동작은 미명시다. 인증 구현은 기존 password-policy와 호환되는 안을 백엔드가 제안하도록 되어 있다.
- 제안 A: `/me`에도 must_change_password 추가. 변경 전 세션은 /me·change-password·logout만 허용하고 업무/관리 API는 403 `password_change_required`. 프론트도 변경 화면으로 이동한다. 변경 성공 뒤 세션을 재발급해 이전 세션을 폐기한다. 최초 변경 제한을 새로고침·직접 URL에도 서버가 보장한다.
- 제안 B: 비활성화/관리자 초기화 때 해당 사용자의 기존 세션을 폐기한다. 자기 계정 비활성화와 마지막 활성 관리자 비활성화는 400 `account_protection`으로 거절한다. 초기화 계정의 다음 로그인은 변경을 강제한다.
- 제안 C: 비밀번호 검증은 서버를 기준으로 최소 12자·4종 중 3종·추측 가능한 정보 금지 등 password-policy와 맞춘다. 잠금(5회/30분), 90일 만료·최근 5개 재사용 금지·외부 OTP의 이번 필수 구현 적용 범위를 지혜님·오현님이 공통 문서에 명시하도록 요청한다. 프론트가 규정을 임의 완화하거나 전부 구현된 것으로 쓰지 않는다. 잠금/만료/OTP가 적용되면 필요한 응답 필드와 오류 처리도 함께 반영한다.
- 제안 D: 세션 만료는 서버 설정으로 관리하고 만료 시 401 unauthorized를 반환한다. 쿠키 SameSite=Lax, Path=/, 운영 HTTPS에서 Secure, HttpOnly, 상태 변경 요청의 Origin 검사로 같은 출처 프록시 정책을 맞추는 안을 검토한다. 세션 유효시간 수치는 백엔드가 운영안과 함께 제시하고 공통 반영 전 UI가 카운트다운을 만들지 않는다.
- 영향: 지혜님 인증·계정 API·세션/정책 저장, 수언님 새로고침·403 분기·비밀번호 안내, 원민님 잠금/권한/폐기 시험. 규정 내용을 바꾸는 요청과 앱 적용 범위를 정하는 요청을 구분한다.
- 계속할 일: 로그인/변경/401/역할 메뉴 UI는 Mock으로 진행한다. 미정 정책을 가입 폼·버튼의 확정 조건으로 넣지 않는다.
- 검토 상대: 지혜님·오현님, 시험 원민님. 상대 근거/공통 반영 커밋: 없음. 실제 연결: 미실행.

## H04 · 시간 제한·진행 중 문의·배포 프록시

| 항목 | 기존 | 제안과 영향 |
| --- | --- | --- |
| 제한 시간 | 지연·장애 안내 원칙만 있고 웹 상한/오류 상태 미명시 | FastAPI→support timeout은 504 `{error:{code:"upstream_timeout",message:"처리 결과를 확인하지 못했습니다."}}`, 연결 장애는 503 upstream_unavailable 제안. timeout 수치는 실제 경로 측정·최악 시도 시간 근거로 지혜님·다혁님이 제시. 클라이언트 제한은 서버 상한보다 여유 있게 설정, 자동 POST 반복 없음. FE 결과 미확정/동일 ID 수동 재시도 영향 |
| context | 선택 문자열, attempt 기본 1·3 이상 이관 | 보완 시 원 질문 유지, 이전 보완 질문/사용자 답을 차례대로 context에 누적. 서버 최대 4000자 제안, 초과 400 invalid_input으로 명시적 안내하며 묵시 절단 금지. 숫자는 변경 제안이며 확정 전 UI 한계로 적용하지 않음 |
| 재조회·복구 | GET my-requests는 있으나 진행 중·처리 실패 항목/중복 진행의 응답 미명시 | 문의 목록에 처리 중/완료/실패와 nullable result를 나타내는 processing_status를 추가하는 안. 같은 소유자의 진행 중 request_id 재전송은 새 작업을 만들지 않고 HTTP202 처리 중 응답으로 구별하는 안 검토. 이는 공통 웹훅 route를 바꾸지 않는 FastAPI 웹 계층 제안이며 반영 시 C01에 별도 정의 필요. 프론트는 새로고침 후 목록을 조회하고 자동 재제출하지 않음 |
| 프록시 설정 | 브라우저 /api→프론트 프록시→backend, C07 서비스·포트는 확정. 서버용 대상 변수 없음 | 서버 전용 `BACKEND_ORIGIN` 추가 제안. 로컬 http://127.0.0.1:8000, Compose http://backend:8000으로 설정하며 이름만 .env.example에 추가. 브라우저 NEXT_PUBLIC 노출 금지. 환경변수를 늘리지 않는 기존 배포 방식이 있으면 그 방식에 어댑터를 맞춤 |

- 영향: 지혜님 웹 오류/처리 상태/멱등 경계, 다혁님 처리 상한, 원민님 동일 키·장애 시험, 수언님 API client·대기/복구 표시·서버 프록시. DB 컬럼 변경이 필요하면 지혜님이 자기 마이그레이션을 검토하며 수언님은 SQL을 만들지 않는다.
- 계속할 일: M01~M08·대기·결과 미확정 UI와 메모리 내 동일 ID 재시도는 진행한다. 202·processing_status는 미승인 Mock 제안 시나리오로 분리하며 공통 성공 응답으로 간주하지 않는다. 새로고침 자동 복구·운영 상한의 실제 연결만 대기한다.
- 검토 상대: 지혜님·오현님, 시간/시험 영향 다혁님·원민님. 상대 확인/반영 커밋: 없음. 실제 연결: 미실행.

## 이후 기록할 근거

상대의 실제 검토가 오면 제안 ID별로 상대 HANDOFF 링크·검토 의견·채택/수정/거절·오현님 공통 반영 절/커밋을 이 문서에 덧붙인다. 실제 연결 뒤에는 실행일·환경·입력(비밀값 제외)·기대/실제·HTTP 상태·증거·재시험을 기록한다. 현재 해당 근거는 없으며 작성란을 합의 완료로 대신 채우지 않는다.

버그 전달은 관찰 증상·재현 입력·기대/실제·환경/버전·마스킹된 로그를 사용한다. 상대 파일을 대신 고치지 않는다. 지금 작성한 것은 정책/계약 보완 제안이며 관측한 서버 버그 보고가 아니다.
