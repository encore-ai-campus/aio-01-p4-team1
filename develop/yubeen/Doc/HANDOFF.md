## H-Y01 · search 검증 오류와 분류 필터의 세부 계약

- 연결/요구: C03, RAG-02·03. 작성: 2026-11-03, 유빈님 담당 문서. 상태: **제안, 검토 전**.
- 기존: [API-CONTRACT 3절·8절](../../../docs/API-CONTRACT.md)은 search 정상/빈 결과 200, 장애 503, 일반 입력 오류 400 원칙을 정한다. request_id/query/type/access_levels/top_k의 예시는 있으나 필수 여부·자료형·빈 값·top_k 비기준값·인증 실패 응답의 세부 모양이 없다. 공통 DB에는 문서 유형의 필수 열/분류 매핑이 없다.
- 제안: search의 request_id는 비어 있지 않은 1~64자 문자열, query는 앞뒤 공백 제거 뒤 1~500자 문자열, type은 분류 문맥 문자열로 받고 최초 버전에서는 검색 제외 필터로 쓰지 않는다. access_levels는 `[all]` 또는 `[all,it]` 두 집합만 허용하며 빠짐/빈 목록/미지 값/it 단독을 거절한다. top_k 누락은 3, 3 이외 값은 400으로 거절해 공통 운영값을 유지한다. 입력 불량은 HTTP400·ok=false·evidence=[]·reason=invalid_input, 필드 오류는 codes 목록에 담는 안을 검토한다. 인증 누락/불일치는 HTTP401·ok=false·evidence=[]·reason=unauthorized로 구별하고 임베딩/DB를 호출하지 않는다. codes의 구체 값은 각 입력 필드명을 기반으로 계약에 열거하도록 제안한다.
- 입출력 영향: 기존 유효한 공통 예시는 그대로 유지한다. 비정상 요청의 HTTP/응답이 명시되므로 다혁님 본체의 오류 분기·Mock과 원민님 시험이 바뀐다. 이는 제안 형식이며 기존 503/search_unavailable을 임의 대체하지 않는다.
- 검토 상대: 다혁님(C03), 원민님(C08). 공통 반영: 오현님이 API-CONTRACT 3절·8절 검토. request_id/query 길이와 인증 형식의 일관성은 지혜님도 확인 대상이다.
- 계속할 일: 유효한 top_k=3·권한 두 집합의 정상/빈 결과/503 Mock과 SQL 후보 검증. 미확정 입력은 검색/권한 확대로 이어지지 않게 하고, 상세 오류 계약 확정은 별도 반영한다.
- 확인 근거/공통 반영 커밋/실제 연결: 모두 없음·미실행.

## H-Y02 · 원본 권한 메타데이터의 출처와 누락 해소

- 연결/요구: C06·C08, RAG-01·02. 상태: **제안, 검토 전**.
- 기존: [DATA-AND-DB 1절·4절](../../../docs/DATA-AND-DB.md)은 규정 8종·관리자 문서, access_level=all/it, 미정 권한 색인 거절을 정한다. 그러나 `/docs`·본문 응답에 권한이 없을 때 어떤 관리 원본으로 doc_key와 권한을 확정할지는 정하지 않았다. 현재 실제 API 응답/관리자 문서 제공 여부는 확인하지 않았다.
- 제안: API가 제공하는 검증 가능한 권한 메타데이터를 우선 사용한다. 해당 필드가 없는 배포에서는 오현님이 **실제 문서 목록의 doc_key별 all/it 대응표와 관리자 문서 식별자·출처·버전**을 공통 기준으로 배포한다. 유빈님 원본 대장은 그 기준의 버전을 참조하고, 새 문서/표에 없는 키/충돌하는 권한은 계속 색인 거절한다. 모든 규정을 일괄 all로 추정하지 않는다.
- 영향: DB 열·차원·마이그레이션은 바뀌지 않는다. 원본 목록/권한 표와 색인 입력 검증·일반/IT 시험 자료가 필요하다. 관리자 문서가 없다면 원민님이 자료 불일치와 재현을 기록하고 오현님이 제공 경로를 확인한다.
- 검토 상대: 지혜님(C06), 원민님(C08), 오현님(권한 기준·문서 제공). 공통 반영 대상: DATA-AND-DB 1절의 권한 출처 설명 또는 그 절에서 가리키는 관리 표.
- 계속할 일: 확보된 원본 목록·절·길이·해시 조사, 미확인 권한 거절 시험, 확인된 문서의 청킹. 관리자 문서 권한 시험/전체 완료만 미실행으로 둔다.
- 확인 근거/공통 반영 커밋/관리자 문서 확보: 모두 미확인.

## H-Y03 · 삭제·권한 변경·동시 갱신과 복구 운영정책

- 연결/요구: C06·C08·C09, RAG-05·06. 상태: **제안, 검토 전**.
- 기존: 공통 DB는 doc_key 고유키·source_hash·청크 구조와 영속 저장을 정하지만 원문 삭제 동기화, all→it 변경 도중 기존 공개본 처리, 동시 색인 직렬화, 갱신/백업 주기·보관 기간·복구 목표는 정하지 않았다. named volume 사용은 백업 정책 자체가 아니다.
- 제안: 초기 운영은 관리자가 수동 색인하고 정기 자동 삭제/갱신은 켜지 않는다. 한 번에 한 색인 실행만 허용하고 저장 직전 doc_key별 잠금/재확인으로 중복 교체를 막는다. 일반 본문 변경은 준비 완료 후 문서 단위 트랜잭션 교체, 실패 시 이전 성공본을 유지한다. **권한 축소나 삭제가 확인된 문서는 이전 공개본 유지 대상에서 제외**하여 검색 중지 후 변경/삭제를 적용하고 확인 전 검색을 재개하지 않는 방식으로 제안한다. 목록 조회 실패를 삭제로 취급하지 않는다. 삭제는 원본별 404 또는 관리자의 명시적 삭제 목록 등 확정 근거가 있을 때만 처리한다.
- 제안하는 첫 복구 운영안: 새 DB는 지혜님 마이그레이션 후 원본·권한·설정으로 재색인한다. 통합 배포 직전과 색인 변경 전 DB 백업을 만들고 직전 성공본을 다음 검증 완료까지 유지한다. 백업 파일은 저장소에 넣지 않는다. 이후 자동백업 주기·보관 기간·RPO/RTO는 실제 변경 빈도와 복구 시간 측정 뒤 제안하며 현재 수치 목표를 만들지 않는다.
- 영향: 색인 트랜잭션·잠금/검색 중지 경로·배포 점검·백업 관리가 추가된다. 현 테이블에는 active/version 열이 없으므로 중지 방법을 기존 검색 유지보수 상태로 처리할지 DB 구조를 추가할지 지혜님 검토가 필요하다. DDL·함수·마이그레이션·백업 명령은 지혜님 소유다. 권한 축소 중 이전 공개본이 노출되지 않는 시험이 필요하다.
- 검토 상대: 지혜님(C06, 저장/잠금·복구), 다혁님(C03, 검색 중지 시 503 이관), 원민님(C08, 실패/동시 실행·권한 시험), 오현님(C09, 운영·공통 반영). 대상: DATA-AND-DB 4절과 배포/복구 운영 기준.
- 계속할 일: 격리 데이터의 동일 원본 재실행·일반 본문 변경·임베딩/저장 실패 롤백·재시작 전후 비교·새 환경 재색인 준비. 미반영 상태에서 삭제 자동화·권한 변경 안전성·동시 실행·백업 정책 완료를 주장하지 않는다.
- 확인 근거/공통 반영 커밋/재시작·복구 시험: 모두 없음·미실행.

## H-Y04 · 실측 후 임계값 적용 위치와 시간 예산

- 연결/요구: C03·C08, RAG-03·04·07. 상태: **제안, 검토 전**.
- 기존: 공통 기준은 점수=1-cosine distance, top_k=3과 실측 후 임계값 확정을 정한다. 임계값의 설정 소유자·search 필터/본체 분기 중 적용 위치·시간 예산과 재시도 한도는 명시하지 않았다.
- 제안: 첫 측정은 임계값 필터 없이 허용 후보 top3의 원점수를 기록한다. 답 있음/없음/유사하지만 답 없음 질문과 별도 보류 질문으로 후보 임계값을 검토하고, 승인 뒤 **search의 설정 한 곳에서 근거 필터에 적용**, 다혁님 본체는 남은 evidence와 답 검증을 함께 사용하도록 제안한다. 필터 후 0개면 기존 200/no_evidence를 사용한다. 임계값 이상만으로 자동 답변하지 않는다. 값 변경은 설정 버전·재색인 필요 여부·회귀 자료와 함께 남긴다.
- 시간 제안: query 임베딩/DB/search/본체 전체를 따로 3회 이상 측정하고 N·중앙·p95·최대·실패를 기록한다. 본체의 실제 공통 시나리오 시간 제한에서 나머지 단계의 측정 시간을 뺀 예산을 검토해 search 시간 초과를 정한다. 초기에는 search 내부 자동 재시도를 넣지 않고 장애를 503으로 반환하는 안을 제안한다. 수치·재시도 변경은 실측 후 검토한다.
- 영향: search 설정·근거 개수·빈 결과 빈도, 본체 이관률·전체 처리시간, 원민님 경계/장애 사례가 바뀐다. DB 스키마·모델·3072차원·cosine 정확검색·top_k=3은 유지한다.
- 검토 상대: 다혁님(C03, 적용 위치·본체 예산), 원민님(C08, 보류 질문·경계/시간 시험), 오현님(공통 반영). 반영 대상: API-CONTRACT 3절·DATA-AND-DB 4절의 실측 기준/설정 책임.
- 계속할 일: SPEC의 질문·두 청킹 방식·점수/시간 기록 양식으로 측정 준비. 측정 전 임계값·품질률·처리시간 목표 달성을 쓰지 않는다.
- 실제 측정/상대 확인/공통 반영 커밋: 모두 없음·미실행.

## 이후 검토·전달 기록 양식

각 제안 아래에 `검토자·날짜 / 상대 HANDOFF 링크 / 검토 의견 / 수정된 제안 / 오현님 공통 반영 문서·절·커밋 / 내 SPEC 반영 / 실제 연결 확인 입력·HTTP·보고서 / 남은 문제`를 추가한다. 검토 기록이 없으면 제안 상태를 유지한다. 상대 HANDOFF는 링크로 읽기만 한다.

실제 버그가 확인되면 `증상 / 재현 입력 / 기대·실제 / 환경·버전 / 마스킹한 로그 / 영향 / 소유자`를 추가한다. 지금은 실제 버그를 재현하거나 협의를 완료한 기록이 아니다.

## C06 · P1-1 안전성 결함 보완 후 확인 요청 · 2026-11-04 · 전달 전

기존 검토/실행 이력은 보존한다. 지적된 권한 축소 누락·동시 재공개·검증 성공 오판·Mock/DB 중지 불일치·rollback 실패는 Mock/DB-API 더블에서 보완했다. 전체108개 테스트가 통과했으며 실제 PostgreSQL/API/임베딩/n8n은 미실행이다. 상대 동의·공통 반영·외부 메시지 전송 없음.

지혜님 확인 사항:

1. 기존 테이블·updated_at·metadata·FK/고유키/vector(3072)와 현재 버전 지문 매핑이 실제로 맞는지. 새 DDL/컬럼/마이그레이션은 작성하지 않았다.
2. PostgreSQL의 pg_advisory_xact_lock(hashtextextended(...)) 사용 가능 여부, 실제 격리 수준, SELECT FOR UPDATE와 동일 트랜잭션 내 비교·UPDATE/INSERT/청크 교체의 원자성. 모든 색인 쓰기 경로의 동일 문서 잠금 규약 준수가 필요하다. 외부 직접 청크 변경·deadlock·잠금 대기·실패 재실행은 실제 시험이 필요하다.
3. 소유권을 이전한 전용 autocommit=false 연결을 사용한다. SQL 실패/rollback 실패/commit ACK 불명확을 구분하고, 후자의 두 경우 close·재사용 차단한다. 풀/공유 연결은 직접 지원하지 않으며 실제 물리 연결 폐기/대여 해제 규약을 담당자가 확인해야 한다. 불명확한 커밋은 이전 상태 보존 성공으로 처리하지 않는다.
4. all→it 확인 시 본문/제목 오류와 별개로 같은 문서 ID를 유지하며 it/빈 청크 상태로 중지한다. 이후 동일 입력이나 all 입력도 자동 재개하지 않는다. 중지/재개 권한·승인·실제 원본 재확인 조건은 미결정이며 이번에 임의 확정하지 않았다. 청크 없는 기존 행은 보수적으로 검토 대상으로 막는다.
5. 중지 DML 실패·결과 불명확 시 실제 검색을 중단하는 운영 수습이 필요하다. 엔진의 failed 보고만으로 공개 데이터 미노출을 보장하지 않는다. 실제 검색 중지·복구·재개 확인은 배포 전 담당자 합의와 통합 시험이 필요하다.

원민님 전달 준비: 빈 본문/잘못된 제목의 권한 축소, 충돌·미확인 권한 불변, 중지 실패, 중지 후 ID 보존·재실행 거절, 두 스레드 경합과 저장 전 CAS, 임베딩 전체 실패 종료1, rollback 실패·commit 불명확 연결 폐기, 기존 정상/건너뜀/부분 실패 보존. 근거는 tests/test_indexing.py의 SafetyDefectRegressionTests·TransactionFailureRegressionTests·AdditionalTransactionTests 및 Doc/INDEX-RESULT.md 최신 절이다.
