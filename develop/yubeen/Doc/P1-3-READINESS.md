# P1-3 실제 검색 평가 준비 · 2026-11-05

상태: 코스 킷 원본을 로컬에서 읽어 근거 위치와 청킹 구조만 확인했다. DB·OpenAI 추가 호출·n8n·VM 검색은 미실행. 기존 `SEARCH-EVAL.md`의 품질 수치 미측정 상태와 `cases/rag-search.json`의 draft 정답표를 유지한다. 원본 위치와 문서별 SHA256은 `REAL-DOC-INTEGRATION-READINESS.md`를 따른다.

## 평가 도구

`rag_evaluate.py`는 고정된 정답표·원본 해시·두 방식의 동일 조건을 요구한다. Hit@3, 절 Hit@3, 필수 답 문구 포함률, 답 없음 오답률, 권한 누출, 503 실패, 실행 환경·설정·측정 출처를 Fake 결과에서 집계한다. 이번에 빠져 있던 MRR을 `mrr`로 추가했다. 각 답 존재 질문·반복의 첫 정답 문서 순위 역수(없음·503은 0)를 합산하고 전체 답 존재 시도 수로 나눈다. 아직 실제 결과 수용은 막혀 있고 `mode=fake`만 허용한다. 실제 정답표가 얼지 않아 현재 Q01~Q16의 Hit@3·MRR 분모는 0이다.

## 실제 원본 두 청킹 방식의 구조 비교

기존 `rag_prepare.chunk_document`를 원본 8개에 적용했다. 권한 인수는 함수 실행을 위한 임시값일 뿐 문서 권한 확정이 아니다. 길이는 유니코드 문자 수이며 `content`는 제목·절 접두어를 포함한다.

| 방식 | 문서별 청크 수 (장비/메일/회의실/비밀번호/개인정보/VPN/사고/SW) | 총수 | 본문 길이 최소/중앙/최대 | content 길이 최소/중앙/최대 | 완전/부분/거절 | 빈 절 제외/길이 거절 |
| --- | --- | ---: | --- | --- | --- | --- |
| `section` | 5/4/4/5/4/4/3/4 | 33 | 13/90/156 | 26/113/182 | 8/0/0 | 0/0 |
| `300` | 2/2/1/2/1/2/2/2 | 14 | 9/253.5/300 | 35/295.5/358 | 8/0/0 | 0/0 |

두 방식 모두 각 청크의 doc_key·절·원문 범위·해시를 추적할 수 있고 `coverage_with_exclusions=true`였다. 이 8개에는 빈 절과 8000바이트 초과 거절이 없었다. 긴 절은 이 원본에서 section 방식의 최대 본문 156자로 거절되지 않았고, 300 방식은 문서당 300자 단위 분할로 최대 본문 300자다. 원문 범위 장부상 누락 0이지만 실제 DB 저장·검색에서의 보존은 미검증이다. 청크 수·길이만으로 검색 품질이나 우수 방식을 결정하지 않는다.

## 실행 절차와 결정 필요 사항

1. 오현님이 8개 문서별 all/it 권한, 특히 security-incident와 privacy를 확정하고 공통 문서와 Q08 충돌을 해결한다. 다혁님과 검증된 IT 권한 전달·본체 소비·이관 경계를 합의한다.
2. Q01~Q11의 실제 절 제목·필수 답 문구를 현재 원본 해시와 함께 원문 대조해 검색 전에 별도 버전으로 고정한다. Q12~Q13의 답 없음과 Q14~Q16의 관리자 원본·권한도 확인한다. 검색 결과에 맞춰 기대값을 바꾸지 않는다.
3. 지혜님 격리 DB DDL·권한·접속 및 쓰기 대상 확인 후 두 청킹 방식의 실제 색인을 순차 실행한다. 동일 테이블에 두 방식을 혼합하지 않는다. 문서/청크 수·해시·실패·비용 출처를 남긴다.
4. 같은 모델/차원/cosine/top3·질문·권한으로 방식별 3회 검색하고 HTTP 응답, 후보 순위·절·원문 범위·시간·실패·권한 누출을 기록한다. 현재 오프라인 평가기는 Fake 입력만 받으므로 실제 기록 수용 경로를 검증·추가한 뒤 실측 지표를 산출한다.

현재 검증: 구조 비교와 기존 Fake 평가만. 실제 검색 Hit@3·MRR·근거 포함률·권한 안전성·시간·비용은 모두 미측정이다.

회귀 실행: 전용 `.venv`의 Python unittest 172개 통과(기존 171개 + MRR 순위/503 시험 1개), JavaScript 16개 통과. `git diff --check` 통과. Q12의 연차와 Q13의 CPU/프로세서 표현은 현재 8개 원본에서 발견되지 않았지만, 전체 의미 검토 전까지 답 없음 확정으로 승격하지 않았다.
