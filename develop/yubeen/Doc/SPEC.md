## 문서 → 절 → 청크 → 임베딩 → DB 필드 매핑 · RAG-01

입력은 문서 목록과 각 문서의 실제 제목·본문·확인된 권한이다. 목록/본문의 응답 모양은 P0에서 기록한다. 본문에 권한이 없다는 이유로 `all`을 채우지 않는다. API 메타데이터가 권한을 제공하지 않는 경우의 명시적 매핑 출처는 HANDOFF H-Y02 제안 대상이다.

| 단계/원천 | 저장·사용 필드 | 변환과 예상 결과 |
| --- | --- | --- |
| 문서 `name` | `rag.documents.doc_key` | 원본 식별자를 유지. 파일명 확장자 제거 등 API의 식별 규칙을 대장에 기록, 임의 새 ID로 바꾸지 않음. UNIQUE |
| 제목·권한·조회 경로 | `title`, `access_level`, `source_url` | `all`/`it`만 허용. `source_url`은 키를 포함하지 않는 원문 경로, 출처가 없으면 NULL |
| 원본 전체 본문 | `source_hash` | UTF-8 본문의 SHA-256. 줄바꿈은 LF로 통일하고 다른 공백/문구는 보존하는 개인 기본구현. 해시 규칙을 대장에 명시 |
| 성공한 저장 시각 | `updated_at` | 원본 수정시각이 제공되지 않으면 성공한 색인 저장시각으로 기록하고 그 의미를 명시. 실패한 갱신을 성공 시각으로 덮지 않음 |
| 문서 PK | `rag.chunks.document_id` | `rag.documents.id` 참조. doc_key·문서 제목을 청크 테이블 별도 필수 컬럼으로 만들지 않음 |
| 원문 순서의 청크 | `chunk_no` | 문서 안에서 0부터 증가하는 개인 기본구현. `(document_id,chunk_no)` UNIQUE. 같은 입력/설정은 같은 순서 |
| `##` 제목 | `section` | 원문의 절 제목을 보존. `###` 이하 내용은 해당 절에 둠. 서문은 `서문`, 절 없는 문서는 `본문`으로 표시하고 가상 표제임을 표본에 기록 |
| 절 본문 | `content` | 제목·절 제목·본문을 줄바꿈으로 결합한 근거 텍스트. 문구·숫자·목록 순서 보존. 동일 텍스트를 임베딩하고 evidence.text로 반환 |
| 결합된 `content` | `content_hash` | 실제 임베딩 입력의 UTF-8 SHA-256. 본문·문서/절 제목이 바뀌면 변경 감지 |
| content 임베딩 결과 | `embedding`, `embedding_model` | 유한 수치 3072개와 `text-embedding-3-large` 저장. 빈/0벡터·다른 차원·모델 혼입은 저장 거절 |
| 청크 추적 정보 | `metadata` JSONB | 개인 기본구현 키: `chunking`, `chunking_version`, `source_hash`, `section_order`, `part_no`. 글자 비교청크는 원문 범위와 포함 절 목록도 기록. 권한은 이 복제값 대신 documents 필드를 기준으로 판정 |
| 검색 결과 조인 | `evidence.doc/section/text/score` | doc_key/section/content/계산 점수. DB PK·벡터·Credential·제한 문서 내용은 응답에 추가하지 않음 |

출력은 원본 대장, 문서별 절/청크 수와 길이, DB 매핑 표본, 성공/거절 내역이다. 빈 문서·중복 doc_key·본문 조회 실패·미확인 권한·임베딩 실패는 해당 문서의 오류로 기록하고 성공 건수에 넣지 않는다. 통과 기준은 모든 저장 청크가 원문·절·권한으로 역추적되고, 벡터 길이·모델·FK·고유키가 공통 구조와 일치하는 것이다. 규정 8종과 관리자 문서 누락은 별도로 보고한다.

## 문서 권한과 기본청킹 · RAG-02·04

**개인 기본구현**은 `##` 절당 청크 1개, overlap=0이다. 제목 앞 본문이 있으면 서문 청크를 만들고, 비어 있는 절은 생성하지 않는다. 문서 제목·절 제목을 붙인 content를 임베딩한다. 목록·표·코드 블록을 일반 텍스트로 보존하고 코드 블록 안의 `##`는 절 경계로 쓰지 않는다. 모델 입력 한도를 넘는 절은 잘라 버리지 말고 거절/길이 기록 후 분할 개선 대상으로 남긴다.

비교구현은 문서 본문을 **유니코드 문자 수 300자, overlap=0**으로 순서대로 자른다. 300은 본문 길이이며 제목 접두어 길이는 별도 센다. 문서 경계는 넘지 않는다. 여러 절이 걸친 청크는 `section`에 포함 절 제목을 원문 순서로 연결하고 metadata에 원문 범위를 둔다. 두 방식은 같은 원본·권한·접두어 구성 규칙·모델·차원·cosine 정확검색·top_k=3·질문을 사용한다. 운영 기본값은 비교 결과만으로 몰래 바꾸지 않는다. 변경 이유와 실패 질문을 기록한다.

| 입력/경계 | 예상 결과 | 오류·통과 기준 |
| --- | --- | --- |
| 확인된 all 문서, 일반 직원 | SQL 검색 대상에 포함 | doc/절/content 추적 가능 |
| 확인된 it 문서, 일반 직원 | SQL 검색 대상에서 제외 | 후보·evidence·답변 LLM 입력·일반 로그에 본문 노출 0건 |
| 확인된 it 문서, IT팀 | all과 it 문서에서 검색 | 질문에 답이 있는 관리자 절을 찾는지 양성 사례도 확인 |
| access_level 누락/다른 값 | 색인 거절 | all로 추정/강등 금지, 원본 식별자와 사유만 기록 |
| 질문에 “나는 관리자” 포함 | 본체가 검증한 access_levels 유지 | 질문 문자열로 it 추가 금지 |
| SQL 대상 3개가 모두 it 문서인 데이터 | 일반 직원은 제외된 집합에서 다시 상위 3개 | 전역 top3를 먼저 뽑아 나중에 필터하는 구현 거절 |

권한 신뢰 경계는 직원 조회를 맡는 본체와 내부 인증이다. search가 요청 본문의 권한을 독자적으로 직원 권한으로 증명했다고 기록하지 않는다. 잘못된/누락 권한 입력의 상세 오류 계약은 H-Y01 제안이며 그 입력으로 검색을 실행하지 않는 조건은 유지한다.

## search 입출력과 SQL 의미 · RAG-03

| 입력 필드 | 적용 의미 | 확인 사례 |
| --- | --- | --- |
| request_id | 한 호출/재시도의 추적 식별자 | 문서 본문·개인정보 대신 식별자로 오류 연결 |
| query | 검색어를 공통 모델로 3072차원 임베딩 | 공백만 입력·잘못된 자료형은 SQL/임베딩 전 검증. 상세 오류 코드는 H-Y01 |
| type | 본체가 전달하는 분류 문맥 | 공통 DB에 필수 type 열/분류 매핑이 없으므로 초기 정확검색의 추가 필터로 쓰지 않음. 필터 도입은 H-Y01 제안 대상 |
| access_levels | 검증된 `[all]` 또는 `[all,it]` | 누락·빈 목록·알 수 없는 값·it 단독 입력으로 권한 확대 금지 |
| top_k | 공통 기준값 3 | 기본 운영·비교 모두 3. 누락/3 이외 값 처리의 상세 계약은 H-Y01에 제안, 임의로 가변 top_k 운영하지 않음 |
| X-Team-Key | 내부 웹훅 인증 | 키를 URL·로그·보고서에 넣지 않음. 미인증 호출은 검색하지 않음 |

SQL 구현에서는 documents와 chunks를 document_id로 조인하고, **documents.access_level이 검증된 목록에 속하는 행만 후보**로 삼는다. 같은 모델의 벡터만 비교한다. pgvector cosine 거리 연산자 `<=>`의 오름차순으로 정확히 정렬한 뒤 3개를 제한한다. 동점은 doc_key와 chunk_no 순으로 안정화한다. 바인딩 매개변수로 질의 벡터·권한·개수를 전달하며 사용자 문자열을 SQL에 이어 붙이지 않는다. 이 문서는 SQL 생성물이나 마이그레이션이 아니다.

점수는 거리 d에 대해 `1-d`이며 클수록 가깝다. 확률·정답률·0~1 보장값으로 해석하지 않는다. 계산값을 임의 반올림/잘라내기한 뒤 정렬하거나 판정하지 않는다. 동일 `(document_id,chunk_no)`는 한 번만 반환하고 서로 다른 절을 문서 단위로 합쳐 버리지 않는다. 정확검색을 확인할 때 실제 질의·실행계획과 활성 인덱스를 기록하고 전체 허용 후보의 거리 정렬 결과와 대조한다.

| 상황 | HTTP·예상 응답 내용 | 오류·통과 기준 |
| --- | --- | --- |
| 유효한 검색, 후보 있음 | 200, ok=true, evidence에 doc·section·text·score, reason=null | 길이 1~3, 유한 점수 내림차순, 허용 문서만 포함 |
| 검색 가능한 후보가 없음 | 200, ok=true, evidence=[], reason=no_evidence | DB 오류를 빈 결과로 바꾸지 않음 |
| 임베딩/DB/시간 초과 장애 | 503, ok=false, evidence=[], reason=search_unavailable | 실패를 부분 근거 성공으로 바꾸지 않음, 본체가 이관 |
| 규정 밖 질문이지만 벡터 후보는 있음 | 검색 결과와 실제 점수를 관찰 | top3가 나왔다는 사실은 답 존재의 증명이 아님. 임계값 미확정 상태에서 억지로 no_evidence 판정하지 않음. 본체 답 검증과 이관도 별도 확인 |
| 인증·입력 불량 | 공통 오류 원칙 적용, 검색 미실행 | 세부 필드 규칙/인증 실패 형식은 H-Y01 반영 전 제안으로 남김 |

RAG-03 통과에는 정상·0개·1개·3개·동점·일반/IT 권한·임베딩 장애·DB 장애의 실제 응답과 본체 소비 확인이 필요하다. Mock 통과를 실제 연결 통과로 기록하지 않는다.

## 색인 갱신·재시도 · RAG-05

기본구현은 문서 단위로 준비 후 교체한다. 원본과 권한 확인 → 청킹 → 모든 임베딩 검증까지 기존 성공 색인을 유지한다. doc_key가 같고 source_hash·제목·권한·모델·차원·청킹 설정이 모두 같으면 건너뛰고, 재실행해도 중복을 만들지 않는다. 해시가 같아도 권한·제목·청킹 설정 변경은 건너뛰지 않는다.

한 문서의 교체는 기존 문서 ID를 유지한 문서 메타데이터 갱신·이전 청크 교체·새 청크 저장을 **한 DB 트랜잭션**으로 처리한다. 단계마다 별도 연결을 여는 노드 조합이 같은 트랜잭션이라고 가정하지 않는다. 원자적 저장을 수행할 연결 방법을 확인하고 DB 함수/스키마가 추가로 필요하면 지혜님에게 요청한다. 트랜잭션 실패는 전체 롤백하고, 다음 실행은 실패 문서부터 재처리한다. 원문 출현이 사라진 것만 보고 전체 테이블을 비우지 않는다.

| 입력/실패 | 예상 결과 | 통과 기준 |
| --- | --- | --- |
| 같은 원본·설정 2회 | 두 번째는 건너뜀, 총 문서/청크 수·해시 불변 | 고유키 충돌을 성공으로 숨기지 않음 |
| 한 문서 본문 변경 | 그 문서 청크 교체, 줄어든 청크의 잔여 행 없음 | 다른 문서 수·해시 불변, 변경 절 검색 반영 |
| 임베딩 중단/저장 실패 | 해당 문서 이전 성공본 유지, 실패 보고 | 부분 새 벡터와 이전 벡터 혼합 없음 |
| 일부 문서 실패 후 재실행 | 성공 문서 건너뜀, 실패 문서 재처리 | 누락·중복 없이 완료 여부를 문서별 기록 |

**원문 삭제·all→it 변경 도중 이전 공개본 처리·동시 색인·갱신 주기**는 공통 기준에 없다. H-Y03의 구체 제안만 기록한다. 검토 전 운영 자동 삭제/예약 갱신이나 권한 변경 안전성 완료를 주장하지 않는다. 동일 입력 재실행·본문 변경·장애 롤백은 격리 데이터에서 계속 검증한다.

## 재시작 유지·복구 · RAG-06

입력은 성공 색인의 문서/청크 수·해시·모델·차원과 고정 검색 결과, 지혜님이 제공한 마이그레이션/볼륨 정보다. 결과는 아래 전후 비교와 실제 소요시간이다.

1. 기준 상태의 문서별 청크 수, source/content 해시, 권한, 모델/차원, 고정 질문 top3를 기록한다.
2. 지혜님/오현님이 관리하는 환경에서 n8n만 재시작한 뒤 **재색인 없이** 동일 DB 검색을 비교한다.
3. 같은 named volume을 유지한 PostgreSQL 재시작 뒤 DB 연결 회복·건수·해시·권한·검색을 비교한다. 재시작과 볼륨 삭제를 혼동하지 않는다.
4. 지혜님이 분리한 새 DB에 마이그레이션을 적용하고 동일 원본·권한·청킹 설정으로 전체 재색인한다. 운영 DB를 비우지 않는다. 복구 시작~검증 종료 시간·임베딩 토큰·실패/재시도·비용 산정 출처를 기록한다.
5. DB 백업 복원은 지혜님이 별도 환경에서 수행한다. 유빈님은 복원 후 동일 매핑·건수·해시·권한·검색을 검증한다. 백업이 없으면 미실행으로 남기며 재색인 결과를 백업 복원 성공으로 쓰지 않는다.

PK 자체가 달라질 수 있는 새 환경은 doc_key·chunk_no·content_hash로 비교한다. 임베딩 재생성 시 순위·점수가 달라지면 실제 차이와 정답 포함 여부를 기록한다. 통과 기준은 재시작 전후 저장 데이터 유지, 새 환경에서 누락/중복 없는 재생성과 권한 시험, 실패 후 재시도 확인이다. RTO/RPO·보관/자동백업 주기는 H-Y03 제안이며 측정 전 목표 달성으로 쓰지 않는다.

## 검색 평가 질문과 판정 · RAG-04·07

아래는 **검색 전 작성할 정답표의 시작안**이다. P0에서 실제 제공 원문 버전의 문서·정확한 절 제목·필수 답 문구를 대조해 고정하고 그 이후 검색 실행한다. 원문과 다른 기대는 실행 전에 근거와 함께 수정한다. 실행 결과가 나쁘다는 이유로 정답을 바꾸지 않는다.

Q14~16은 원문을 받기 전 구체 내용을 꾸미지 않는다. 누락 시 미실행으로 남긴다. RAG-03의 빈 후보·동점·오류·잘못된 권한은 질문 품질 집계와 분리해 기능 사례로 시험한다.

두 청킹 방식을 순서대로 같은 격리 DB에 색인하고 동일 질문을 보낸다. 두 색인을 공통 테이블에 동시에 섞지 않는다. 데이터/설정 해시와 실행 순서를 기록한다. 질문별 3회 반복하되 첫 회와 후속 회를 구분하고 캐시·임베딩 API·동시 요청 조건을 적는다. 실패한 호출도 시간/장애 집계에 남긴다.

- doc hit@3 = 기대 문서가 상위 3개에 있는 답 존재 질문 수 / 답 존재 질문 수.
- 절 hit@3 = 기대 문서와 기대 절을 함께 찾은 질문 수 / 답 존재 질문 수. 비교청크가 절을 걸치면 원문 범위/포함 절 목록으로 확인한다.
- 근거 포함률 = 필수 답 문구를 실제 top3 content가 뒷받침하는 질문 수 / 답 존재 질문 수. 문서명만 맞은 결과와 구별한다.
- 권한 누출 = 허용되지 않은 후보·evidence·LLM 입력·일반 로그의 본문 노출 건수. 요구는 0건이며 미관측 경로는 미확인이다.
- 규정 밖/답 없음 질문은 hit@3 분모에서 빼고, top_score·답 검증·이관 결과와 부적절 자동 답변 건수를 별도 기록한다.
- 시간은 query 임베딩, DB 조회, search 전체, 본체 전체를 구별해 단조 시계로 잰다. 표본 수·최소/중앙/최대·p95를 기록하고 p95 계산은 정렬된 N개 중 올림(0.95×N)번째 값으로 통일한다. 준비/색인 시간은 검색 시간에 섞지 않는다.

검색 품질률과 처리시간의 통과 수치는 미확정이다. 기능 불변조건을 먼저 확인하고 두 방식의 실측·실패 목록을 제출한다. 점수 기준 후보는 답 있음/없음/유사하지만 답 없음 질문의 분포에서 제안하고, 별도 보류 질문으로 재확인한다. 자동 답변 최종 판단은 본체의 답 검증과 함께 확인한다. 임계값 위치·시간 예산은 H-Y04에서 다혁님/원민님 검토를 요청한다. 예시 점수나 다른 실험 수치를 복사해 통과값으로 쓰지 않는다.
