## 목적과 사용자

일반 직원은 공개 규정에서, IT팀은 공개 규정과 관리자 전용 문서에서 해결 근거를 찾는다. 문서와 절이 추적되는 근거를 본체에 주고, 허용되지 않은 본문은 검색 후보·LLM 입력에 들어가지 않게 한다. 근거가 없거나 검색이 실패하면 본체가 구별해서 이관할 수 있어야 한다. 원본 규정이 바뀌거나 서비스가 재시작되어도 같은 기준으로 색인을 갱신·복구한다.

## 후순위

- 절이 모델 입력 한도를 넘을 때의 하이브리드 청킹 고도화, 질문 다시 쓰기, 재순위화. 기본/비교 방식에서 발견한 실패부터 기록한다.
- HNSW 등 근사 인덱스, 차원 축소, 모델 변경, 파티션·대량 배치·자동 갱신. 현재 정확검색·3072차원·top_k=3을 먼저 완성한다.
- 삭제 자동 동기화·예약 갱신·세대별 무중단 전환. 공통 정책 보완은 HANDOFF의 제안이며 현재 확정 기준으로 취급하지 않는다.
- FAQ를 규정 청크로 합치기, 팀 신규 문서 추가. 원본 규정·FAQ 의미와 데이터 범위를 임의로 변경하지 않는다.

## 바로 진행할 것과 외부 준비가 필요한 것

전처리·정답표·청킹 비교·계약 Mock은 자기 폴더에서 바로 진행한다. 지혜님의 DB가 준비되면 이미 정해진 테이블·모델·차원으로 연결한다. 마이그레이션을 새로 협의하는 단계를 추가하지 않는다. data-api 또는 관리자 문서가 없으면 누락 사실을 기록하고 확보된 원본으로 전처리를 계속하되 전체 색인·권한 검증 완료로 표시하지 않는다.

확정되지 않은 것은 검색 임계값, 본체와 나눌 시간 예산, 누락된 세부 정책이다. 실측·구체 제안은 계속 작성하고, 공통 반영 전에는 새 정책을 확정 계약으로 적용하지 않는다. 지원 담당·검토일은 미정이며 개발 착수 조건이 아니다.
