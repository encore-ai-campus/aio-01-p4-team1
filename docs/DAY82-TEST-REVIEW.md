# 11/09 추가 시험 · 결과와 남은 문제

**새 실서비스 요청 83회**를 실행했다. 기존 app 모드를 유지했으며 서비스 코드·인증키·배포·재시작은 변경하지 않았다. 장애 설정은 해제하고 복구를 확인했다. **공식 공통·팀 전체 통과나 최종 제출 완료를 뜻하지 않는다.** 리허설·최종 제출 확정은 사용자 승인 전이다.

전체 판정과 실행 ID는 [검토 집계](../runs/day82-reviewed-results-20261109.json)에 있다. 아래 숫자는 각각 다른 검사 집합이므로 합쳐서 통과율로 쓰지 않는다.

TM-06은 세 회차 모두 같은 ID의 티켓·알림 각 1건과 duplicate=true를 확인했다. 원본의 WM-03 알림 정책 pending은 임의로 해소하지 않았다. WF-05의 기존 it-admin-runbook 조건도 유지하면서 실제 IT 전용 security-incident가 노출되지 않는지 추가 확인했다.

기존 **N14 숫자 검증 결함은 미수정**이다. 원문 90일을 91일로 바꾼 합성 초안과 거절 verdict를 넣으면 보정 코드가 자동 답변으로 승격하는 것을 [원본 노드 오프라인 검사](../runs/isolated-node-fault-check-20261109.json)에서 재확인했다. **실제 배포 서비스에서 잘못된 답변을 받은 사례로 기록하지 않는다.**

## 실제 VM에서 하지 않은 시험

- **WF-10 LLM 장애:** 공식 `tools/flow.py`의 llm down은 외부 등록 스크립트로 공용 provider Credential을 교체한다. 독립 main에 해당 스크립트가 없고, 요청 한정 LLM 장애 기능도 배포돼 있지 않다. 운영 키·구성·재시작을 바꾸는 시험은 실행하지 않았다.
- **TM-14 verifier 거절 주입:** 전용 Mock/시험 설정이 필요하다. 요청별 강제 예외는 verifier 거절과 다르므로 이 사례의 성공으로 대체하지 않았다.
- 두 경로의 일부 원본 노드 처리는 오프라인 합성 입력으로만 확인했다. 실제 HTTP·저장·복구 전체 통과로 계산하지 않는다.
- 실패 뒤 DLQ는 pending으로 보존된다. 복구는 수동 재요청이며 자동 재처리·삭제 성공을 확인한 것이 아니다. 알림은 `/alerts` ACK·DB 저장까지 확인했으며 외부 메신저 수신·관리자 화면 확인은 별도다.

## 종료 상태와 기록 정정

[종료 후 읽기 확인](../runs/post-test-state-20261109.json)에서 app 모드·장애 해제, 공개 로그인 페이지 및 n8n health HTTP 200, 활성 4종의 비교한 구현 필드와 main 일치를 확인했다. 각 시험 묶음 전후 컨테이너 ID·이미지·시작 시각·상태와 활성 버전도 동일했다. 이는 main 전체 배포나 모든 화면 경로의 성공을 보장하는 검사는 아니다.

이번 묶음의 업무 기록은 티켓 **+41**, 알림 **+46**, DLQ **+5**다. 직원 6·문의 73·RAG 문서 8/청크 33은 전후 동일했다. 앞선 10:09 보고서의 문의 71과 이번 시작 값 73의 차이는 이번 실행 전에 있었으므로 이번 시험 증가분으로 계산하지 않았다. 기존 데이터·기록은 삭제하지 않았다.

검사기에서 두 문제가 발견돼 원래 기록을 보존하고 재평가했다.

- 검색 점수의 숫자를 전화번호로 오인해 일시 중단했다. [최초 중단 기록](../runs/team-interrupted-20261109.json)과 [실제 출력 재조회](../runs/team-detector-review-20261109.json)를 남겼다. 문자열 개인정보는 없었으며 기록된 요청을 재전송하지 않고 재개했다.
- WF-07의 부분 마스킹 표시를 내보내면서 별표까지 제거해 원본 judge가 실패로 표시했다. 실제 실행 **491·515·539**에서 별표·masked=2·본인 상태를 읽어 재확인했다. 원본 반복 JSON의 최초 판정은 보존하고 [검토 집계](../runs/day82-reviewed-results-20261109.json)에 정정 이유를 연결했다. 서비스 응답이나 사례 기대를 바꾼 일이 아니다.

준비 도구의 [오프라인 검사](../runs/test-harness-offline-checks-20261109.json)는 새 서비스 시험 건수에 포함하지 않는다. 원본 JSON의 pending·최초 검사 값과 직접 검토 후 판정은 구분하며, 최종 판단은 검토 집계를 따른다. 실제 수집 보조 파일은 비공개 환경 의존성이 있어 제출용 독립 러너로 포함하지 않았다.

결과·문서의 [비밀 검사](../runs/secret-scan-remaining-20261109.json)는 기존 검토 예외를 적용한 작업 트리 텍스트 범위이며, Git 과거 이력·이미지 전체 검사가 아니다. 이번 반영은 **중간 결과 보관**이다. 리허설·최종 제출·서비스 수정은 사용자 승인 없이 이어서 수행하지 않는다.
