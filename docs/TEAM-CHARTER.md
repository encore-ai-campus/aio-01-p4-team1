파일명은 workflows/team1- 접두사로 사용합니다. search/handoff는 역할별 파일 충돌을 줄이기 위한 모듈 분리 제안입니다. 수언님에게 프론트·백엔드 연결을 전담시키는 안은 아닙니다.

**조율 기준:** 기존 준비 자료의 희망 분야를 참고하고, 11/02 회의에 명시된 유빈 RAG 방향을 반영했습니다. 지혜의 C형 연결 담당과 원민의 연동·시험 취합은 새 추천이며 직접 확인해야 합니다. 각자 수락 여부·부담되는 작업·협업 상대를 짧게 확인해 확정합니다.

최신 아키텍처 28쪽은 6명 기준 리드·오케스트레이션·RAG·연동 안정성·어댑터·QA를 예시로 듭니다. 위 안은 화면 디자인의 별도 책임을 반영해 조정했습니다. 각 구현자가 자기 시험과 기술 문서를 작성하고 원민은 취합, 수언은 UI 시험·시연을 지원합니다. 원민에게 모든 시험을 맡기지 않습니다. 지혜의 연결 부담이 크면 C 범위·화면 기술을 먼저 줄이며 팀장이 웹 전체를 대신 구현하는 것을 기본안으로 삼지 않습니다.

## 2. 목표

사내 IT 문의에 근거를 제시하고, 근거 부족·긴급·보안·권한 요청을 안전하게 이관하며, 외부 장애에도 정해진 응답과 기록을 남깁니다.

## 3. 범위

[TOPIC.md](TOPIC.md)의 6유형을 기준으로 합의합니다. A 핵심 검증 → 작은 C 웹서비스 → 여유 시 외부 알림 1개를 추천합니다. C 선택은 미정이며 연결 담당·환경을 확인한 뒤 확정합니다.

## 4. 협업 규칙 제안

- 파일당 최종 편집 담당자 1명. 다른 사람의 파일 변경은 담당자와 공유합니다.
- 수업 공통 계약·시험 원본 판정은 유지합니다. 시험 제외는 강사 확인 범위와 사유를 별도 기록합니다. 내부 계약 변경은 팀장과 합의 후 설계서부터 갱신합니다.
- 질문은 ‘시도한 것·막힌 지점·오류·필요한 도움’으로 남깁니다. 긴급 통합 장애 외에는 정한 확인 시간에 함께 봅니다.
- 의견 충돌은 사람 평가가 아니라 문서·시험 기대값·실행 결과로 확인합니다.
- 막힌 뒤 30분 안에 팀 공유, 1시간이면 강사에게 도움 요청합니다.
- 키는 Credential에만. 커밋 전 비밀 검사. VM 배포는 팀장만 기본 브랜치에서 수행하고 공통 시험을 확인합니다.
- 81일차 8교시 기능 동결, 이후 시험·수정·문서·발표에 집중합니다.
