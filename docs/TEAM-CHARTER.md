## 목표와 범위

오케퐁 직원 6명의 사내 IT 문의에 권한이 허용된 규정의 근거로 답하고, 근거가 없거나 긴급한 문의는 IT팀 티켓·알림으로 이관한다.
문의 범위·계정·저장은 [TOPIC](TOPIC.md), API·실행 설정은 [API 계약](API-CONTRACT.md)을 따른다.
공개 회원가입은 없고 관리자가 계정을 발급한다. 텔레그램은 필수 기능·시험·시연이 끝난 뒤 검토한다.

## 협업 규칙

- 각 담당자는 현재 main의 README·설계서를 기준으로 변경 범위·입출력·확인 방법을 정리하고 한 단계씩 구현·확인·커밋한다. 계약 변경이 필요하면 지정 상대와 협의하고 팀장 확인 후 설계서와 코드를 반영한다. 공통 시나리오 판정은 임의로 바꾸지 않는다.
- 일반 개발 담당자는 자기 담당 파일만 수정한다. 상대·공통 파일 변경은 재현 입력·변경 이유·영향을 정리해 소유자에게 요청한다. 공통 계약·제출 문서는 오현님이 반영한다.
- PR에는 변경·확인 결과·남은 문제를 적는다. 공통 기본 브랜치 병합과 팀 VM 배포는 리드가 관리한다.
- 워크플로우·연동 변경 때마다 공통 시나리오를 다시 검사하고, 커밋 메시지에 실제 통과 수를 적는다. 미실행이면 사유를 적고 통과로 표시하지 않는다. 현재 공식 도구의 준비 상태와 후속 실행 범위는 [공식 시험 도구 안내](../tools/README.md)와 [에이전트 규칙](../AGENTS.md)을 따른다.
- VM에는 팀장만 기본 브랜치에서 배포하며, 배포 후 공통 회귀 시험을 한다.
- 커밋 전 `tscan staged`, 제출 전 `tscan scan .`으로 비밀값을 검사한다. 도구를 실행하지 못했다면 사유를 기록하고 검사 통과로 표시하지 않는다. 키·비밀번호·연락처를 문서·JSON·로그·캡처에 노출하지 않는다.
- 81일차 8교시 기능 동결, 이후 시험·수정·문서·발표에 집중한다.
- 막힘은 30분 안에 팀에 공유하고, 1시간 이상 지속되면 팀장과 함께 강사에게 공유한다.

지원 페어 기본안은 다혁님↔원민님, 유빈님↔지혜님, 수언님↔오현님이다. 당시 기록에는 팀원별 동의가 남아 있지 않아 전원 합의로 표시하지 않는다. 지원자는 입력·실행법·실패 재현·다음 작업을 함께 파악하고, 파일 수정은 주 소유자가 한다. 부재 시 소유권 변경이 필요하면 오현님이 범위·기간을 알린다.
현재 제출본의 워크플로우는 루트 `workflows/` 아래에 관리한다. 제출용 경로는 [독립 제출본 안내](../SUBMISSION.md)를 따른다.

상세 협의 책임과 단계별 연결 기준은 [COORDINATION](COORDINATION.md)을 따른다. 지원 담당은 파일 수정 권한을 자동으로 받지 않는다.
