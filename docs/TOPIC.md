# 오케퐁 사내 IT 헬프데스크 · 주제 제안 초안

> 상태: 팀 논의 반영, 80일차 강사 승인 전. 이 문서의 구현 계획은 완료 결과가 아니다.

## 1. 주제와 해결할 문제

오케퐁 직원 6명이 반복적인 사내 IT 문제의 근거 있는 해결 절차를 빠르게 받고, 자동 답변할 수 없는 문의는 IT팀에 정확히 접수되도록 한다.

- 사용자: 제공된 가상 직원 6명. IT팀 김민지·정우성은 관리자 역할을 맡는다.
- 구현 조합: 선생님 분류의 C형(Next.js 직원·관리자 화면 + FastAPI + n8n). 먼저 A 기본 동작으로 공통 시나리오를 확인한 뒤 웹 화면과 API를 연결한다.
- 추가 기능: 텔레그램 입구는 필수 기능과 시연이 완성된 경우에만 검토한다.

## 2. 기술 지원 범위

| 문의 유형 | 근거 자료·예 | 처리 원칙 |
| --- | --- | --- |
| 계정·인증 | 비밀번호 재설정, 계정 잠김 | 규정의 절차를 안내하고 직접 계정 조치는 이관 |
| 네트워크·VPN | VPN 접속 오류 | 근거를 찾아 안내 |
| 메일·문서·개인정보 | 메일함, 문서 공유, 개인정보 규정 | 권한이 허용된 문서만 근거로 사용 |
| 기기·프린터·회의실 | 장비 문제, 프린터, 회의실 장비 | 자가 점검 안내, 현장 조치 필요 시 이관 |
| 소프트웨어 | 설치·사용 문의 | 승인·사용 절차 안내, 실제 설치 요청은 이관 |
| 보안 사고 | 피싱, 기기 분실, 유출 의심 | 긴급 티켓·알림, 규정에 있는 초동 조치만 안내 |

자동 답변은 사용자가 볼 수 있는 근거가 검색되고 검증을 통과할 때만 한다. 정보가 부족하면 보완 질문을 하고 `attempt >= 3`이면 이관한다. 근거가 없거나 검증에 실패하면 추측하지 않고 이관한다. 검색 점수 기준값은 실제 측정 후 확정한다.

## 3. 데이터와 저장

- 수업 data-api: 규정 8종, FAQ 6종, 가상 직원 6명, 기존 티켓 4건 및 공통 시험의 데이터·장애 조건에 사용한다.
- 오케퐁 PostgreSQL: 새 문의, 티켓, 알림, 계정, 세션, 처리 상태를 저장한다.
- RAG: 제공 규정을 청킹·임베딩해 우선 n8n In-Memory 벡터 저장소에서 검색한다. 재시작 후 `oke-index`로 재색인한다.
- MongoDB·InfluxDB·PGVector는 이번 필수 구현 범위에 넣지 않는다.

## 4. 화면·계정·티켓

- 직원: 로그인 → 질문 → 답·근거 또는 이관 결과 → 내 문의·티켓 상태 확인.
- 관리자: 직원 계정 생성·비활성화·비밀번호 초기화, 티켓 목록·긴급 알림 확인, 담당자·답변·상태 변경.
- 공개 회원가입은 없다. 첫 관리자 계정을 안전하게 준비한 뒤 관리자가 제공된 나머지 직원의 계정을 만든다. 임시 비밀번호는 첫 로그인 때 변경한다.
- 티켓 상태는 `접수 → 처리 중 → 완료`, 긴급도는 `보통`·`긴급`으로 시작한다. 같은 `request_id`의 티켓은 한 번만 생성한다.
- 화면은 FastAPI만 호출한다. FastAPI는 로그인·권한·입출력 검증·저장과 n8n 호출을 담당하고, n8n은 분류·RAG·답변·검증·이관 판단을 담당한다.
