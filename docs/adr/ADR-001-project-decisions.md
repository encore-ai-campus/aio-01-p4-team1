# ADR-001: 오케퐁(OKE-Pong) 핵심 아키텍처 및 협업 의사결정 기록

- **상태**: 팀장 배포 기준. 기술 선택은 공통 계약을 따르고 6절의 지원 배정은 기본안으로 적용하되 팀원 확인을 기록한다.
- **일자**: 2026-11-03
- **기준·관리**: 오현님과의 기획 대화·공통 문서. 팀원 전원의 검토·합의 완료를 뜻하지 않는다.

본 문서는 프로젝트 초기 기획 및 코덱스(Codex) 설계 세션에서 결정한 주요 아키텍처·데이터·협업 방식을 기록한다. 모든 팀원과 AI 에이전트는 아래 결정된 방향을 임의로 되돌리거나 다른 기술 스택으로 대체하지 않는다.

---

## 1. 단일 워크플로우 대신 역할별 5개 워크플로우 분리
- **배경**: 하나의 거대한 n8n 워크플로우에 색인·검색·본체·이관·오류 처리를 모두 넣으면 여러 팀원이 동시에 수정할 때 JSON 충돌이 발생하고 장애 격리가 어렵다.
- **결정**:
  - `oke-support` (다혁님): 공통 웹훅 진입점, 입력 검증, 분류, 보완 질문, 답변 생성·검증, 최종 응답 조합
  - `oke-index` (유빈님): 사내 규정 청킹·임베딩·pgvector 적재 및 재색인
  - `oke-search` (유빈님): `access_levels` 사전 필터링 및 pgvector 유사도 검색 서브 워크플로우
  - `oke-handoff` (원민님): 담당자 이관 티켓 생성(`key=request_id` 멱등), 알림 전송, DLQ 기록
  - `oke-errors` (원민님): Error Trigger 기반 예상 밖 워크플로우 실패 최종 안전망
- **기대 효과**: 워크플로우 JSON 파일 소유권을 나누어 동시 편집 충돌을 줄이고, 공통 시험(`flow.py`)과 웹 요청이 동일한 `oke-support` 진입점을 공유한다. 분리만으로 모든 Git 충돌이 없어지는 것은 아니다.

## 2. 공개 회원가입 제외 및 관리자 발급 + 첫 로그인 비밀번호 변경 강제
- **배경**: 사내 IT 헬프데스크 특성상 외부인이 임의로 가입하면 직원 사칭 및 권한 상승 위험이 있다.
- **결정**:
  - 공개 회원가입 화면·API를 두지 않는다.
  - 최초 IT팀 관리자 1명은 환경변수(`BOOTSTRAP_ADMIN_PASSWORD`)로 1회 부트스트랩 생성한다.
  - 나머지 직원 계정은 관리자가 제공 직원 6명(`app.employees`) 중에서 선택해 발급하고 임시 비밀번호를 부여한다.
  - 임시 비밀번호로 첫 로그인하거나 비밀번호가 초기화된 계정은 `must_change_password=true` 상태가 되며, 비밀번호 변경 전까지 업무 API 호출을 `403 password_change_required`로 차단한다.
  - 비밀번호 정책은 사내 규정(`password-policy`)과 맞추되, P0/P1 필수 범위는 **서버 기준 최소 12자 + 3종 조합 + 본인 이름/ID 포함 금지**로 고정하고, 이력 테이블·잠금·외부 OTP는 P2 고도화 범위로 분리한다.

## 3. PostgreSQL + pgvector 단일 RDB 통합 (In-Memory 벡터스토어 배제)
- **배경**: In-Memory 벡터 저장의 재시작 후 휘발을 피하고, 여러 서비스가 같은 업무·검색 데이터를 사용하도록 PostgreSQL과 pgvector로 통일한다. SQLite도 파일 영속 저장은 가능하지만 이번 공동 서버·벡터 저장 기준으로 채택하지 않았다. 문서별 권한은 저장소 선택과 별도로 검색 조건에서 검증한다.
- **결정**:
  - 제공 원본 데이터(직원 6명, 규정 8종, FAQ 6종, 기존 티켓 4건)와 고장 주입 시험은 `data-api`를 사용한다.
  - 실제 로그인 계정·세션·새 문의·새 티켓(`T-2001~`)·알림·DLQ는 PostgreSQL `app` 스키마에 저장한다.
  - 규정 문서 메타데이터와 청크 임베딩(`text-embedding-3-large`, `vector(3072)`)은 같은 PostgreSQL 인스턴스의 `rag` 스키마(`pgvector`)에 저장하고 `named volume`으로 영속화한다.
  - 검색 시 LLM 프롬프트가 아니라 SQL `WHERE access_level = ANY(...)` 절에서 문서 권한(`all` vs `all,it`)을 먼저 필터링한다.

## 4. 개발 당시 `develop/<이름>/` 개인 폴더 격리 및 `P0(기반) → P1(필수 MVP) → P2(고도화)` 단계화
- **배경**: 6명이 동시에 AI 코딩 에이전트를 사용할 때 같은 폴더를 건드리면 Git 충돌이 반복되고, 상대방 구현이 끝날 때까지 대기하면 3일 일정 내에 통합할 수 없다.
- **결정**:
  - 일반 담당자는 본인 `develop/<이름>`에서 작업한다. 오현님은 `develop/ohyun`과 루트 공통 문서·계약·제출 취합을 관리한다.
  - 각 폴더 안에 표준 작업 문서(`README.md`, `Doc/TODO.md`, `Doc/SPEC.md`, `Doc/IMP-PLAN.md`, `Doc/HANDOFF.md`)를 두어 자신의 폴더 문서와 루트 공통 계약만 읽고도 즉시 개발을 시작할 수 있게 한다.
  - 개발 순서는 **P0(기반·스캐폴딩·Mock 검증) → P1(필수 MVP·실제 연동·중복/동시성/반복 시험) → P2(선택 고도화)**로 고정한다.

## 5. 팀장 기본안 우선 적용 및 `HANDOFF.md` 기반 변경 관리
- **배경**: 모든 세부 사항을 매번 상호 승인받으려 하면 초기 개발 착수가 지연된다.
- **결정**:
  - 루트 [API-CONTRACT.md](../API-CONTRACT.md)와 [DATA-AND-DB.md](../DATA-AND-DB.md)에 정의된 기본안대로 구현할 때는 별도 사전 협의 없이 즉시 구현한다(상대 서비스 미준비 시 동일 계약의 Mock 사용).
  - 계약 변경이나 예외 정책 추가가 필요할 때만 본인 폴더의 `Doc/HANDOFF.md`에 제안을 기록하고, 영향받는 상대 확인 후 팀장(오현님)이 루트 공통 문서에 한 번만 반영한다.

## 6. 제출 산출물 3종 책임 분담 및 상호 백업 기본안
- **배경**: 필수 제출 문서 3종(워크플로우 설계서, RAG 아키텍처 설계서, 실행 결과서)과 발표 준비가 막판에 누락되지 않도록 초안 작성자와 백업 담당을 명확히 지정한다.
- **결정**:
  - **필수 문서 초안 책임**:
    - [WORKFLOW-DESIGN.md](../WORKFLOW-DESIGN.md): 다혁님 (본체 설계·분류·라우팅) + 원민님 (이관·오류·재시도 보조)
    - [RAG-ARCHITECTURE.md](../RAG-ARCHITECTURE.md): 유빈님 (청킹 비교·임베딩·권한 필터·실측)
    - [EXECUTION-RESULT.md](../EXECUTION-RESULT.md): 원민님 (공통 14 + 팀 5+ + LLM 3회 반복 결과 집계) + 다혁님 (동작 설명 확인)
    - 최종 취합·검토·PDF/이미지 잘림 점검 및 제출: 오현님
  - **역할 간 백업 페어**:
    - 워크플로우/안정성 페어: **다혁님 ↔ 원민님**
    - RAG/DB·인프라 페어: **유빈님 ↔ 지혜님**
    - 화면/통합 페어: **수언님 ↔ 오현님**

  - 팀원별 지원 가능 여부는 아직 확인 전이다. 백업은 실행법·입출력·실패 재현을 함께 파악하는 역할이며 상대 파일 수정 권한을 자동으로 받지 않는다.
  - 실제 작성·지원·확인 상태는 [팀 헌장](../TEAM-CHARTER.md)에 기록한다. 이 문서는 전원 합의나 최종 승인 기록을 대신하지 않는다.
