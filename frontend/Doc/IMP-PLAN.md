# 직원·관리자 화면 · IMP-PLAN

주 담당: **이수언**. 지원 담당은 추가 배정.

> 상태: 단계 구성 초안. 모든 단계 미실행. 담당자가 SPEC의 요구 ID·실제 수정 파일·확인 명령을 채운 뒤 한 단계씩 구현한다.

## 파일 경계

`frontend/`의 화면·API 클라이언트. `backend/`와 워크플로우 JSON은 연결 담당에게 변경을 요청한다.

## 1단계 · 계약·화면 목록

- [ ] 할 일: API-CONTRACT의 웹 API별 요청·응답·오류 예시를 백엔드와 맞춘다. 화면 목록과 상태별 예시를 적는다.
- [ ] 연결된 SPEC ID: 담당자 작성
- [ ] 생성·수정 파일: 담당자 작성
- [ ] 확인 명령·시나리오: 담당자 작성
- [ ] 통과 기준: 합의한 예시로 각 화면 상태를 설명할 수 있음
- [ ] 실제 확인 결과·남은 문제·커밋: 실행 뒤 기록

## 2단계 · 화면 골격·임시 응답

- [ ] 할 일: Next.js 실행 뼈대와 API 호출 모듈을 만들고 계약 예시로 화면을 개발한다. 임시 응답 사용을 명시한다.
- [ ] 연결된 SPEC ID: 담당자 작성
- [ ] 생성·수정 파일: 담당자 작성
- [ ] 확인 명령·시나리오: 담당자 작성
- [ ] 통과 기준: 개발 서버 실행과 화면별 정상·오류 상태 확인
- [ ] 실제 확인 결과·남은 문제·커밋: 실행 뒤 기록

## 3단계 · 실제 API 연결

- [ ] 할 일: 로그인·질문·본인 문의·관리자 기능 순으로 FastAPI에 연결한다.
- [ ] 연결된 SPEC ID: 담당자 작성
- [ ] 생성·수정 파일: 담당자 작성
- [ ] 확인 명령·시나리오: 담당자 작성
- [ ] 통과 기준: 직원/관리자 계정으로 주요 경로를 실제 실행
- [ ] 실제 확인 결과·남은 문제·커밋: 실행 뒤 기록

## 4단계 · 통합·제출 근거

- [ ] 할 일: 팀 VM에서 질문부터 티켓 처리까지 확인하고 가린 캡처를 제공한다.
- [ ] 연결된 SPEC ID: 담당자 작성
- [ ] 생성·수정 파일: 담당자 작성
- [ ] 확인 명령·시나리오: 담당자 작성
- [ ] 통과 기준: 실제 서버 연결과 개인정보 노출 여부 확인
- [ ] 실제 확인 결과·남은 문제·커밋: 실행 뒤 기록

## 단계별 에이전트 요청 예시

```text
이 역할의 SPEC.md와 IMP-PLAN.md, 공통 API-CONTRACT.md를 읽어.
내가 지정한 한 단계만 구현해. 담당 경로를 지키고 공통 계약 변경이 필요하면 영향을 알려줘.
수정 파일·검사 결과·내가 실행할 확인 명령을 보고해.
구현과 실제 확인을 구분하고, 확인 전 통과 체크를 하지 마.
```

단계 완료 후 담당자가 직접 확인하고 커밋한다. n8n push·test는 수업 규칙대로 사람이 수행한다. 다음 단계 진행 여부는 담당자가 판단하며, 기능이 연결되면 관련 회귀 시험을 한다.
