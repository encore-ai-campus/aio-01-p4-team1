## 시간 관리 원칙

- 각 시나리오의 배정 시간(30초~55초)은 화면 로딩을 포함한 최대 한도이며, 합계는 정확히 **300초(5분)**입니다.
- 응답을 기다리는 동안에는 다음 단계의 검증 포인트(예: "지금 보시는 구간은 SQL 사전 권한 필터가 작동하는 단계입니다")를 한 문장으로 간결하게 설명합니다.
- 만약 특정 호출이 제한 시간을 넘기면 그 자리에서 반복 클릭하지 않고 즉시 아래 비상 대응(Fallback)으로 넘어가 전체 발표 시간을 지킵니다.

## 비상 대응 매뉴얼 (VM 네트워크 또는 외부 OpenAI 지연 발생 시)

### 1. 전환 기준
- **네트워크/서버 지연:** 페이지 로딩 실패, 5xx 응답, 또는 단일 요청이 8초 이상 무응답일 때.
- **OpenAI API 일시 지연:** 실시간 LLM 호출 시간이 단계별 예산을 초과할 때.

### 2. 비상 대응 A — 사전 녹화 영상(MP4) 즉시 전환 (1순위 권장)
1. 발표 전 별도 창에 띄워 둔 시연 녹화 영상(MP4)으로 화면을 전환합니다.
2. **전환 멘트:** *"실시간 외부 API 응답이 시연 시간 예산을 넘어, 사전에 실서버에서 동일 조건으로 촬영한 실행 화면과 DB 검증 영수증으로 이어서 보여드리겠습니다."*
3. 진행 중이던 시나리오 마커(WF-01 / WF-02 / WF-02b / WF-03 / WF-05 / 관리자 티켓) 위치부터 재생하여 5분 내에 시연을 완주합니다.

### 3. 비상 대응 B — 로컬 격리 스택(`oke-local`) 전환 (사전 기동된 경우에만 사용)
시연 전에 로컬 스택(`http://localhost:3001/login`)이 이미 기동·점검되어 있는 경우에만 사용하며, 시연 도중 새로 빌드하거나 초기화하지 않습니다.
```sh
docker compose --env-file local/.private/compose.env \
  -f compose.vm.yaml -f compose.local.yaml -p oke-local ps
```
로컬 스택 화면을 사용할 때는 *"격리된 로컬 예비 환경 화면"*임을 명확히 안내합니다.
