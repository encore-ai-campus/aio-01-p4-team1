# tools · 공식 수업 시험 도구 원본

[flow.py](flow.py)는 선생님 수업 저장소의 79일차 도구를 수정 없이 포함한 파일이다. 출처·원본 커밋·SHA-256은 [COURSE-SOURCE.json](COURSE-SOURCE.json)에 기록한다.

이 main 안에 원본을 포함했으므로 파일을 가져오기 위해 다른 브랜치나 로컬 수업 저장소를 참조할 필요가 없다. 원본은 Python 3.10 이상과 표준 라이브러리를 사용하며, 게시 등 일부 명령에는 실행 환경의 Docker·n8n이 필요하다.

원본을 추가한 당시 단계는 **원본 준비 완료**였다. 당시에는 웹훅 인증 처리, 현재 워크플로우·시나리오와의 호환성 확인, 실제 check·push·test를 진행하지 않았다.

원본 `push`는 n8n 가져오기·게시·재시작을 수행하고, `fault`·`llm`·초기화 명령은 대상 서비스 상태를 변경한다. 원본 준비 단계에서는 도구를 실행하지 않고 원본 해시와 Python 구문만 확인했다. 후속 작업은 사용자가 지정한 범위와 대상에서 진행한다.

## 11/09 실제 확인과 남은 한계

아래 인증·단회 확인 뒤 [후속 시험](../docs/DAY82-TEST-REVIEW.md)을 추가했다. 공통 정상 LLM 9유형의 새 3회 반복·팀 정상 10유형 반복·요청 한정 티켓 장애·기존 티켓 지연·Error 자동 발화 및 복구·벤치까지 실행했다. 실패·사전 조건 미충족·실서비스 미실행은 보존했으며, 원본 CLI 전체 실행이나 완성된 제출용 호환 러너 추가로 표시하지 않는다.

- 기존 backend 컨테이너 내부에서 인증키를 전달한 [빈 질문 1건](../runs/webhook-auth-check-20261109.json)이 예상대로 HTTP 400에 도달했다. 키 누락·위조 등 인증 조건 전체 검사와는 다르다.
- 저장소 밖 보조 파일이 원본의 HTTP 함수·`judge`를 재사용해 [장애 설정 없는 공통 11유형·14요청](../runs/common-no-fault-20261109.json)을 실행했다. 원본 판정에서 처리하지 않는 `route_in`·서술 조건·하위 입력·중복 요청에 대한 판정, DB 및 실행 기록 확인을 보충했다. 원본 입력의 의미·기대는 바꾸지 않고 `request_id`만 새 값으로 지정했다.
- **공식 CLI 원본을 그대로 전체 실행한 결과가 아니다.** 원본 `flow.py`는 그대로이며, 완성된 인증·시나리오 호환 러너가 main에 추가된 상태도 아니다. 환경별 보조 파일은 제출용으로 정리하지 않아 포함하지 않았다. 이 파일과 결과 JSON만으로 같은 부분 실행을 즉시 재현할 수 있다고 안내하지 않는다.
- 최초 단회 시점에는 공통 장애 3유형·팀 전체·LLM 3회 반복·벤치가 미실행이었다. 후속으로 실행한 범위는 위 링크에서 구분한다. WF-10 공용 LLM 장애와 TM-14 실서비스 verifier 주입은 여전히 미실행이다. 새 전체 재현 명령이나 `push` 완료를 기록하지 않는다. 서비스 코드·인증키·배포·재시작을 변경하지 않았고, 시험에 사용한 장애 설정은 해제했다.
